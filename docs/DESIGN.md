# Vale: Design Document

Oct 8, 2026 · Zach Hannum

## Summary

Vale is a GIS for fictional worlds, for desktop, iPad, and iPhone. One world dataset is the source of truth, and each regional map is a projected, styled, labeled view of that dataset.

You draw the world in the app, on a globe. You paint a heightmap (a greyscale image where brightness is elevation) with a soft brush, and the app turns it into vector topography.

The first differentiator is an automatic labeling engine at the level of the ArcGIS Maplex engine, built clean-room as a standalone library. The second differentiator is first-class projection support for a world of any size. The third differentiator is drawing on the sphere, so you never draw on a distorted flat map.

The stack is Rust, with PROJ for projections, GeoPackage for storage, Vello for screen rendering, and Krilla for PDF export.

The app and the labeling library are free and open source, under a dual MIT and Apache-2.0 license.

## Goals and non-goals

Version 1 has ten goals.

- Run on macOS, Windows, Linux, iPad, and iPhone, with pen input on each platform but iPhone. iPad is an equal platform and not a later port. On iPhone, a finger paints.
- Paint a heightmap on a globe with a pressure-sensitive brush, and see it as stepped elevation tints while you paint.
- Turn the heightmap into vector topography polygons with a tool from the toolbox.
- Import equirectangular vector and raster sources, and georeference them (assign world coordinates to them) in under a minute.
- Define a world as a sphere of any radius.
- Make regional maps, each in a projection that fits its region.
- Place labels automatically from stored attributes, at a quality that needs little manual repair.
- When the data, the projection, or the map frame changes, keep manual changes.
- Export an atlas as print-quality PDF, SVG, and raster files.
- Stay compatible with QGIS through open formats.

Version 1 does not include the items that follow.

- Wholesale procedural world generation. This is a permanent non-goal, because the app presents a world that you designed. The Warp mode and the Noise mode of the brush use noise under the brush only, and the Ocean ridge mode and the Range mode use a pattern from a seed near the stroke only. The Basin mode uses a seed for the tributaries inside the outline that you draw only.
- A general painting or illustration tool. The app paints one thing, the heightmap. Photoshop and Illustrator keep color artwork and textures.
- Erosion and other terrain effects. The app prototype tests live rivers, a Carve mode, an Erode mode, a Weather mode, and an Uplift mode of the brush. Those modes erode only where you paint. The prototype also tests a Ridge mode, which raises the land between the rivers, and a Deposit mode, which fills pits and valley floors. The prototype also tests a Warp mode, which moves the ground under the brush by a noise field, a Push mode, which moves the ground in the direction of the stroke, and a Noise mode, which adds fractal noise under the brush.
- Time-based data such as historical borders, and non-spherical worlds. These items come after version 1.
- Real-world GIS analysis such as routing or geocoding.
- A web version.

## Core workflow

The app has one main workflow with four steps, and every design choice in this document serves it.

1. Define the world. You set the radius, the name, and the display units.
2. Draw the world. You paint the heightmap on the globe, run the polygonize tool to get topography polygons, draw rivers and borders as lines, and place data such as cities. You can also import equirectangular vector or raster files that you made in other tools.
3. Make maps. A map shows the layers of the world in one projection. You put a map into a map frame on a page. There you select the projection, turn layers on and off, change the styles for that map, and generate labels from attributes.
4. Make the atlas. You set the scale and the extent of each frame, and you add the title, the legend, and the scale bar. A frame draws the graticule (the grid of latitude and longitude lines). You order the pages and export all of them.

The first start of the app opens on a start screen that lists the projects. A later start opens the project of the last run at its last view. If the last run ended on the start screen, the app opens there. A thread opens the project file, and a loading screen with the name of the project shows until the world opens. Worker threads compile the GPU pipelines of the globe at the start of the app, and the world opens when the file and the pipelines are ready. A pipeline that only some views use compiles when a view first needs it, and its pass draws nothing until then. Each project shows a small picture of its globe, the name of its world, and the date of its last change. From the start screen you make a new world, open a project, rename it, make a copy, and delete it. The app asks before it deletes a project. On the desktop, the File menu has the same actions and a list of the recent projects.

The projects are the project files in the projects folders. On iPad, the app has a local folder and an iCloud Drive folder, and the Files app shows both. On the desktop, the folder is in the data folder of the system. The desktop app also opens a project file from another folder. The name of a project is the name of its world, and a rename does not change the name of the file.

## Technology choices

The app is one Rust workspace. Rust gives one language for the engine and the app, and it has strong crates for geometry, text, and PDF output.

| Area | Choice | Reason |
| --- | --- | --- |
| Language | Rust | One language for all layers. The labeling library stays easy to embed in other tools. |
| App shell and panels | egui, through eframe on wgpu | Fast to build tool panels. It shares one GPU context with the map canvas. |
| Screen rendering | Vello | GPU vector renderer that draws paths, glyphs, and images on wgpu. |
| Text shaping and layout | Parley | Shaping, font fallback, and system font discovery in one crate. |
| Page-space geometry | kurbo | Curves, arc length, and offsets. Vello, Parley, and Krilla all use it. |
| World-space geometry | geo and rstar | Feature types, boolean operations, and an R-tree spatial index. |
| PDF export | Krilla | Text stays text, fonts are subset and embedded, vectors stay vectors. |
| SVG export | Own writer over the display list | The display list is small, so a writer is a few hundred lines. |
| Raster export | Vello, rendered in tiles | Tiles avoid the GPU texture size limit at print resolution. |
| Projections | PROJ, through the proj crate with a bundled build | Accepts a sphere of any radius and covers all common projections. |
| Spherical geometry | Own module, after the design of d3-geo | Clipping and adaptive resampling on a sphere are small, well-known algorithms. |
| Storage | GeoPackage, through rusqlite with bundled SQLite | One file, transactions, and QGIS reads it directly. |
| Vector import | Pure-Rust readers for SVG, GeoJSON, Shapefile, and GeoPackage | No native dependency to package. |
| Raster import | image, tiff, and psd crates | PNG, TIFF with 16-bit depth, and flattened PSD cover the usual tools. |
| Raster reprojection | Own warp in a wgpu shader | PROJ computes a coarse mesh on the CPU, and the GPU interpolates and samples. |
| Heightmap storage | Cube map (six square images that wrap the sphere) in 16-bit tiles | Pixel size stays close to uniform over the sphere, and no pole has a pinch. |
| Heightmap painting | Own brush engine in wgpu shaders | The brush stamps into the cube map tiles, and the stepped preview is one shader pass. |

Three choices need a comment.

GDAL is not in version 1. Fantasy map sources are PNG, TIFF, PSD, and SVG files, and pure-Rust readers cover those. GDAL is hard to package on three platforms, and you can add it later behind the import interface.

The renderer writes a display list (a flat list of paths, glyph runs, and images in page coordinates). Each output backend reads that list. This boundary keeps screen and print output identical, and it lets you replace Vello or Krilla without a change to the map pipeline.

Vello has GPU buffers of a fixed size. The screen backend splits a large list into batches that fit the buffers. It draws each batch to a scratch texture and adds the batch over the last one.

In the Atlas workspace, each map frame has its display lists in page points: the water below the raster layers, the map, and the decorations (the edge labels, the neatline, and the border). The lists change only when the frame or what it shows changes, and not when the page moves. The screen draws them as tiles of 512 by 512 pixels at the scale of the screen, and it renders only the tiles that it does not have. At rest, a pass of the UI renders 8 tiles at most, from the middle of the frame out, and then a ring of tiles around the canvas. While the page zooms, each part of the frame shows the tiles of the nearest scale, and new tiles render at a power of 2 pixels per page point. While a gesture moves a frame or its map, the old tiles move with the map, and a spill (the map at half the resolution in a margin around the frame) fills the shape. The app keeps at most 96 tiles on an iPad and 256 tiles on a desktop, and the tiles that the screen did not draw for the longest time go first.

egui is the least certain choice. It is productive for tool panels, but complex tables and rich text entry take more work than in a web UI. The core crates have no UI dependency, so a move to Tauri or Qt later stays possible.

These choices come from memory and not from a fresh survey. Make sure of the current release status of Vello, Parley, and Krilla before you commit.

The status was checked on 2026-10-08. The current releases are Vello 0.11.0 (2026-10-02), Parley 0.11.1 (2026-08-16), and Krilla 0.8.2 (2026-06-04). All three are before 1.0 and active. The labeling prototype depends on Parley 0.11.1 and on `vello_cpu` 0.3.0, the CPU renderer of the Vello project. It does not depend on GPU Vello or on Krilla.

The app prototype depends on Krilla 0.8.2, eframe 0.36.2, `proj` 0.31.0, and Vello 0.11.0. Vello 0.11.0 and eframe 0.36.2 both use `wgpu` 30, so the GPU Vello backend shares the egui device. On 2026-11-04, Vello 0.11.0 was still the current release.

## Architecture

The workspace has eight crates, and the labeling engine depends on none of the others.

```
                app (egui shell, tools, panels: calls every crate below)

import ──> store ──> sphere ──> style ─────────────────────> render
                                  │                             ^
                                  │ projected geometry          │ placed text
                                  v                             │
                                labeler (standalone library) ───┘
```

Data moves from left to right. The terrain crate is not in the diagram. It writes the heightmap and the topography polygons to the store. The labeler sits beside the main line, takes projected geometry from the style step, and returns placed text to the renderer.

| Crate | Role |
| --- | --- |
| store | Data model, GeoPackage read and write, undo log |
| sphere | Spherical geometry, PROJ wrapper, graticule generation |
| import | File readers, GeoTIFF writer, georeferencing |
| terrain | Heightmap tiles, brush engine, heightmap tools |
| style | Style rules, expressions, symbol generation |
| labeler | Standalone labeling engine. It takes page-space geometry and returns placed text. |
| render | Display list and the Vello, Krilla, SVG, and raster backends |
| app | egui shell, tools, panels |

An unpublished ninth crate, `vale-labeler-demo`, holds the command-line tool for the labeling prototype. The binary of the app crate is named `vale-app`.

An unpublished tenth crate, `vale-globe-proto`, is a prototype that tests pen drawing on the globe. The section "Globe prototype" describes it.

The published crate names take a `vale-` prefix, for example `vale-labeler` and `vale-sphere`. The plain name `vale` is taken on crates.io by an unrelated validation library.

Each map frame runs the same pipeline, on screen and at export.

1. Query. The store returns the features of the visible layers that intersect the extent of the frame.
2. Resample and clip. The sphere crate adds points along each line so that it curves correctly, and it cuts geometry at the edge of the projection.
3. Project. PROJ converts longitude and latitude to page coordinates.
4. Style. The rules turn each feature into symbols.
5. Label. The labeler places text against the projected geometry and the symbols.
6. Emit. The render crate writes the display list.
7. Output. One backend draws the list to the screen, a PDF, an SVG, or a raster file.

Labeling runs after projection, so the engine never sees longitude and latitude. That rule keeps the library usable for real-world maps too.

## Data model and file format

A project is one GeoPackage file. Features live in standard GeoPackage tables, and the app keeps its own records in extra tables in the same file.

| Record | Content |
| --- | --- |
| World | Radius, name, display units, seed, wind, rain shadow |
| Source | Name of the imported file, extents, and the pixels of an imported image |
| Raster | Face size, unit, value range, base level, smoothing, river switch, band line switch, and a copy of the colors and the band names of the style of its layer |
| Raster tile | Raster, level, face, column, row, and the pixels of one tile |
| Image | Width and height in pixels, number of levels, and a copy of the opacity and the blend mode of the style of its layer |
| Image tile | Image, level, column, row, and the RGBA pixels of one tile as a PNG |
| Thumbnail | A small picture of the globe, for the list of projects |
| Symbol | A point symbol that the user adds: a unique name and the text of an SVG file. The symbols are in the order of addition, and they are not in the undo log. |
| Layer | Name, type (raster, image, points, lines, or polygons), visibility, attribute schema (fields with a name, a type, and a default value), link to a source, to a raster, to an image, or to an in-app table |
| Feature | Geometry in longitude and latitude, attributes, a stable ID |
| Style | Ordered rules of one layer, stored as JSON. The style of a raster layer holds its colors: the color stops with their lines, the band colors, the display, the opacity, and the blend mode. |
| Label class | Name, layer, text expression, filter, font family, weight, italic, size, case, letter spacing, color, halo color and width, placement, priority. The map holds its classes as JSON for each layer. |
| Map | Name, projection preset and center, map style, the layers that are off or on in the map, layer styles, label classes |
| Map style | Name, the layers that are off, layer styles, label classes |
| Page | Name, page size in millimeters, units of the page size, paper color, page template, furniture |
| Map frame | Page, map, shape on the page, center, scale, rotation, fill, neatline, border, reference grid, graticule |
| Furniture | Page, kind (text, legend, scale bar, north arrow, or color key), rectangle on the page, link to a map frame of the page, and the properties of the kind as JSON. A legend keeps a changed name or a hidden flag for each entry, keyed by layer and rule. A color key keeps a changed name or a hidden flag for each band, keyed by the name of the band, or by the value of its lower edge for a band with no name. |
| Override | One manual change, keyed by map frame, feature ID, and label class |
| Layout grid | Switch, spacing in millimeters, color. One grid for all pages of the atlas. |
| Page template | Page size, margins, positions of the furniture |
| Atlas | Ordered list of pages |

The order of the layer records is the draw order. The first layer is at the bottom.

The shape of a map frame is a list of rings in millimeters from the top-left corner of the page. The first ring is the outer ring, and the other rings are holes. The frames and the furniture of a page are in draw order. The scale of a frame is a ratio 1:N on the standard lines of the projection. The projection uses the radius of the world, so the ratio is true for any radius. The rotation is in degrees clockwise.

QGIS opens the feature tables directly and ignores the extra tables. The extra tables have the prefix `vale_`. Each one has a row in `gpkg_contents` with the data type `vale`, and QGIS lists only the data types that it knows. That gives interchange with no export step. The topography polygons are feature tables, so QGIS reads them too. A raster layer is not a standard table, and the app exports it as an equirectangular GeoTIFF. The image is four times the face size wide and two times the face size tall. The samples are the 16-bit levels. The file gives the offset and the scale that turn a level into a value in the unit of the layer. The CRS is the sphere of the world, the same as in the feature tables.

Each feature has a UUID in addition to the integer row ID. The UUID never changes, so overrides and styles survive an edit, a replaced file, or a new projection. The UUID is a text column of the feature table.

The world is a row in `gpkg_spatial_ref_sys`: a geographic coordinate system on a sphere of the world radius. Each feature table uses it. Each attribute field is one column. Its type is text, whole number, decimal number, or true or false, and the column type is TEXT, INTEGER, DOUBLE, or BOOLEAN. The default value of a field is the DEFAULT of its column. Each value is null or a value of the type of its field. An imported field with values of more than one type is a text field.

The display units of the world are a text column of the world table, with the value `metric` or `imperial`.

The file has a format version for the extra tables, in the table `vale_meta`. The store has one migration step for each version. When the app opens an older file, it runs the later steps in one transaction. The app does not open a file with a newer version.

The key of a raster tile is the raster, the level, the face, the column, and the row. The face is a number from 0 to 5. The column and the row count tiles of 256 pixels from the corner of the face. Level 0 has the face size of the raster, and the level is always 0 in version 1. A higher level is for finer tiles in a region, which come after version 1. The level field lets those tiles arrive with no change of the file format.

The base level of a raster is the pixel of each place that has no tile. A tile holds 256 by 256 pixels. A tile at the far side of a face can go past the face, and those pixels have the base level.

The pixels of a tile are one compressed blob, and the compression loses nothing. The first byte of the blob gives the codec. Codec 1 takes the difference of each pixel from the pixel to its left. It then compresses the low bytes and the high bytes of the differences with deflate.

A save writes the tiles that changed and removes the tiles that have no pixels now. The tiles and the Raster record go to the file in one transaction. If a raster gets a new face size, the save removes its old tiles.

The tiles of an image never change after the import, and they are not in the undo log. The import writes them while it runs, and the new layer and its Image record are one undo step after that. An undo step that holds an Image record keeps its tiles. When the file opens, when the undo log is emptied, and when an undo step goes, the store removes the tiles of each image that no record holds.

Overrides belong to a map frame and not to the feature. A label that you move in one frame stays where the engine put it in each other frame, also in another frame of the same map.

Each edit is one SQLite transaction with an entry in an undo log table. Undo and redo then work across sessions, and a crash cannot leave a half-written project.

The log is three tables. A step is one edit. A step holds an image of each record and each raster tile that the edit changed, from before the edit. A record is the world, one raster, one vector layer with its features, or the atlas. An image is one compressed blob. The image is empty if the record or the tile was not there. An undo swaps each image of the step with the record or the tile in the file, in one transaction. The step then holds the images from after the edit, and a redo swaps them back. A new edit removes the redo steps. An undo does not put back the next ID of a layer or of a raster, so an ID is not used again.

A step also holds the selection from before the edit and the selection from after it. The selection is the selected features with the key feature, and the selected frame or item of the atlas. An undo selects the selection from before, and a redo selects the selection from after. A restored selection leaves out each feature, frame, or item that is not there, and a frame or an item that is not on the open page. A restored selection that is not the entered frame of the Select tool exits that frame. A change of the selection alone is not an edit, so it makes no step. A step from a file of format version 35 or older has no selection, and its undo does not change the selection. The vertex selections are not in a step.

The log has a size limit, which is 256 MB of images. If the log goes over the limit, the oldest undo steps go first. A step that is larger than the limit goes at once.

The project file holds all the data of the project. The app does not edit the file in place. When you open a project, the app copies the file into its private storage and edits that working copy. Each edit is on disk in the working copy when the edit ends.

The app saves with no action from you. It writes the working copy back as one whole file, in one atomic step. It does this when you close the project, when the app goes to the background, and every few minutes while there are changes. The app also has a Save command, because people expect one. The command writes the working copy back at once. A small mark shows the state of the save. The mark turns during a save, and it is a tick when the file holds each change. On Apple platforms, the write uses file coordination. A sync service such as iCloud Drive then sees only complete files.

If the app stops before it writes back, the working copy keeps each edit, and the app writes it back at the next start.

To move a project between devices, you move or sync the file. The app does not merge. If two devices change the same project, the app keeps both versions, and you pick one.

On iPad, the app keeps each project in one of two folders. The local folder is the Documents folder of the app, and the Files app shows it as "On My iPad > Vale". The iCloud folder is the Documents folder of the iCloud container of the app. The Files app and the Finder show it as "iCloud Drive > Vale". The app owns both folders, so it needs no saved permission to open them again. If the device has no iCloud account, or the build has no iCloud entitlement, the app has the local folder only. The recent list and the working copies are in the Application Support folder of the app, which the Files app does not show.

The app declares the GeoPackage file type to iPadOS, so the Files app opens a project in Vale. A project in one of the two folders opens in place. For a project in another place, the app copies the file into the local folder and opens the copy.

The versions of a project come in two ways. If two devices save the same project while they are offline, iCloud Drive keeps each version, and the start screen asks which one stays. If the project file changes while the project is open, the write-back goes to a new file beside it, with " conflict" after the name.

## World definition and projections

A world is a sphere with one radius, and all stored geometry is longitude and latitude in degrees on that sphere. In PROJ terms the world is `+proj=longlat +R=<radius>`.

A new world starts from a form with a name, a radius, and display units. The form has the radius presets Earth (6,371 km), Mars (3,389.5 km), and the Moon (1,737.4 km), and it takes a free value from 100 km to 100,000 km. The world properties show the same fields, and a change there applies at once. A change of the radius does not change the longitude and the latitude of a feature.

The display units are kilometers or miles. They apply to a distance on the ground: the brush size, the unit of a new scale bar, and the radius. A distance below one kilometer shows in meters, and a distance below one mile shows in feet. The project file holds the radius in kilometers for each choice. A value of a raster layer shows in the unit of that layer.

A projection in the app is a PROJ string plus a name. A custom projection is a preset that you edit and save, so the app needs no projection math of its own.

You can make a map from a region on the globe. In the Atlas workspace, the row "Map from region" opens the globe. On iPad, the row is in the list of the Frame cell. On the desktop, it is in the Add menu. There, a pen or a mouse drags a box, and a finger turns the globe. The region is the range of longitude and latitude of the places in the box. It goes the shorter way around the globe, and a pole in the box gives all longitudes. The app then suggests a projection from the shape and latitude of the region. It puts the map in a new frame on the open page, with the region in view, and the frame opens on the Projection tab. The map and the frame do not keep the region.

In the table, the ground width is the width in degrees of longitude times the cosine of the middle latitude. The first row that matches wins.

| Region | Rule | Suggested projection | PROJ name |
| --- | --- | --- | --- |
| Globe view | The box holds the whole disc of the globe. | Orthographic, centered on the view | ortho |
| Whole world | At least 270 degrees of longitude and 120 degrees of latitude. | Equal Earth | eqearth |
| Polar region | All latitudes at least 60 degrees north or south, or a pole and all latitudes at least 45 degrees on its side. | Polar stereographic | stere |
| Region on the equator | Between 30 S and 30 N, and wider than tall. | Mercator | merc |
| Hemisphere or continent | At least 60 degrees of latitude or of ground width. | Lambert azimuthal equal-area, centered on the region | laea |
| Region taller than wide | More degrees of latitude than of ground width. | Transverse Mercator | tmerc |
| Large mid-latitude region | At least 25 degrees of ground width. | Albers equal-area conic | aea |
| Mid-latitude region, wider than tall | All other regions. | Lambert conformal conic | lcc |

The center of the projection is the center of the region, and a region with a pole has its center on the pole. For the two conic projections, the app sets the standard parallels at one sixth and five sixths of the latitude range. That is a common rule that keeps scale error low across the region. The Projection tab of the new frame shows the reason for the suggestion in one line. The line shows one time. It goes away when the Projection tab of the frame closes or when the projection changes, and it does not come back. The project file does not keep the reason.

The projection editor exposes the parameters that matter: center, standard parallels, and rotation. An oblique aspect (a projection tilted so that its center line follows the region) uses the PROJ `ob_tran` wrapper.

The editor shows distortion while you edit. It draws Tissot circles (equal circles on the sphere that show local stretch after projection) and prints the scale error at the corners of the frame.

The sphere crate generates graticule lines on the sphere and sends them through the same pipeline as features. The graticule belongs to the map frame. The frame turns it on or off, and it holds its interval, its color, and its width. The interval follows the scale of the frame, or you set it by hand. The labels sit where each line meets the frame edge. The frame sets their format: degrees, minutes, and seconds, or decimal degrees. The meridians and the parallels each have a set of labels, and each set has its own switch, text, and placement. The text is the font, the style, the size, the color, and the halo. The placement is inside or outside the edge, the offset from the edge, the orientation, and the sides that have labels. A label lies along its line or is level on the page, and it reads from left to right. An edge of a polygon frame is on the side that it faces. A label that overlaps another label, or is not on its side of the edge, does not show, so the labels at a corner do not overlap. The map labels keep clear of the edge labels inside the frame. The globe and the flat view show a graticule as a view option, and that graticule is not in an export.

A scale bar and a scale value in a text box are correct only where the projection keeps scale. The app measures both at the frame center.

## Import

An import copies the file into the project, and the project stores the extents with the copy. The project then opens complete on each device.

An imported file is a layer. You add it from the Layers panel, and the panel of the layer has three ways to set extents.

- Full globe. This is the default, and it maps the file to longitude -180 to 180 and latitude -90 to 90.
- Four numbers. You type the west, east, south, and north edges.
- Two control points. You click two known places and type their coordinates.

If a full-globe file is not twice as wide as it is tall, the panel shows a warning. A wrong aspect ratio is the most common import error.

The form of a new raster layer can take its levels from an image file, for each kind of raster layer. The form maps the darkest level and the brightest level of the image to two values in the layer.

An image layer keeps the colors and the transparency of an image file. Each pixel holds red, green, blue, and alpha (the opacity of the pixel), and not a value. An example is a drawing of the plate boundaries that you make in another tool. The source is an equirectangular PNG, TIFF, or flattened PSD file, and the extents are the full globe. A PSD file gives its composite image, which has an alpha channel only if the file has no Background layer and was saved with "Maximize compatibility". Photoshop mixes the transparent parts of the composite with white, and the app removes that white. The app reads the file in strips of 256 rows and writes tiles of 256 pixels, so an image of 16,384 by 8,192 pixels loads with a small amount of memory. The file holds the image at the full size and at each half size, down to a width of 256 pixels. The globe draws the first of those levels that is at most four times the display face size wide, which is 8,192 pixels for a face of 2,048 pixels. An image layer is in the one draw order, and a pixel with an alpha of 0 shows the layers below it. The opacity and the blend mode of the layer apply on top of the alpha of each pixel. An image layer has no color stops and no value range, and you cannot paint on it. If the image has no alpha channel or is not twice as wide as it is tall, the panel shows a warning.

After you edit the file in Photoshop or Illustrator, the command Replace from file on the layer loads the file again. The layer keeps its extents, styles, and overrides, and the app draws all maps again.

Stable identity is the hard part when you replace a vector file. For SVG, the app maps each layer by name and each feature by its element ID. If an element has no ID, the app matches features by geometry, and a large edit can then break the match. The app reports each lost match after a replace.

When the app reprojects a raster, the raster loses sharpness, so resolution matters. The rule is that the source needs at least as many pixels per kilometer as the output.

A worked example shows the size of the problem. An Earth-size world at 16,384 by 8,192 pixels has 2.4 km per pixel at the equator. A 2,000 km regional map at 3,000 pixels wide needs 0.67 km per pixel. The world raster is 3.7 times too coarse for that map.

The app has two answers. A regional source with partial extents draws over the world source inside its area. For coastlines, borders, and rivers, use vector layers, because those stay sharp at any scale.

## Drawing on the globe

The world view is a globe that you rotate, in the orthographic projection. You draw on it directly. All drawing tools work in sphere coordinates, so the same tools also work in a map of any projection. A switch shows the world as a flat map, and the same tools work there.

The globe keeps the shapes of each vector layer between frames. It makes them again only after a change to the view, to the layer, or to its style. A feature, a line, or a polygon that is all on the far side or all off the screen is left out.

This removes the main pain of the old workflow. You no longer paint on an equirectangular image, where shapes stretch toward the poles. You no longer paint in several projections and join the parts.

### Levels of a vector layer

A large vector layer has simplified copies at four levels. On an Earth-size world, the levels are 1 km, 4 km, 16 km, and 64 km. A level is an angle, so a world of another size uses the same copies.

The simplification keeps the shared edges of polygons. It splits the boundaries of the layer into arcs between the points where three or more features meet. It simplifies each arc one time, and each feature that has the arc gets the same points. Where two simplified lines cross, it puts back points until no lines cross. A feature that is smaller than a level is not in the copy of that level.

The globe and the flat view draw the coarsest level that is finer than one pixel. A map frame on the screen keeps its display lists at each zoom of the page, so it draws the coarsest level that is finer than one pixel at the highest zoom. If that level is not ready, the views draw the next finer level that is ready, or the full geometry. A map frame composes its lists again when a level is ready.

The copies of each layer build on a worker thread, after the first draw of the layer. An edit builds the copies of only that layer again, after the edit stops. A layer with fewer than 20,000 points has no copies.

Edits, snapping, the attribute table, pick, and the export use the full geometry. A layer with a mask draws its full geometry.

### Heightmap

A heightmap is a raster layer of values with meters as its unit. A world can have other raster layers of values, for example precipitation. Each one has the same store, brush, and preview. A new world has no raster layer.

The world does not mark one raster layer as its height. Each raster layer with the unit `m` is a height layer. Sea level, the rivers, and the brush modes that move ground work on a height layer only. A tool that needs a height takes a layer as its input. Nothing else in the app needs a height layer.

A raster layer is a layer in the one draw order, with the vector layers. It has an opacity. The globe and the flat view draw each visible raster layer in that order, and a layer shows the layers below it through itself as its opacity says. Each raster layer has a blend mode, one of the 12 W3C modes, and the default is Normal. A layer with another mode draws in an offscreen group, which the view blends with the layers below. The flat view, the globe, and the map frames use the same modes. A map frame draws each raster layer that the map of the frame shows, in the projection of the frame and clipped to the shape of the frame. It smooths the layer by the minimum feature size at the scale of the frame, where 1 pt is 1/72 inch. Below the lowest layer is a ground of one plain color. A new raster layer goes above the top raster layer.

A raster layer holds a value that changes smoothly from place to place. A layer of classes, such as a number for each biome, is not in version 1.

A raster layer is a 16-bit greyscale cube map. Each of the six faces splits into tiles, and the project stores only the tiles that you painted.

An equirectangular image is the wrong store. It spends most of its pixels near the poles, and a round brush becomes a wide ellipse there. On a cube map with equal-angle spacing, a pixel covers close to the same ground everywhere.

A raster layer has one face size, which is the number of pixels along the edge of a face. For a height layer, the size is high enough that a regional map uses the same raster layer as the world map. A layer such as precipitation or pressure needs less. You pick the face size when you add a raster layer. The app offers 1,024, 2,048, 4,096, and 8,192 pixels. The default is 8,192 for a height layer and 2,048 for each other layer. The Raster record stores the face size.

The app shows three values next to each size:

- The ground per pixel at the equator, for the radius of the world.
- The size of an equirectangular world map of equal detail, which is four times the face size by two times the face size.
- The memory of a layer that is painted all over, before compression.

These numbers are for an Earth-size world.

| Face size | World map of equal detail | Ground per pixel | Pixels across a 1,000 km region | Memory when painted all over |
| --- | --- | --- | --- | --- |
| 1,024 | 4,096 × 2,048 | 9.8 km | 100 | 13 MB |
| 2,048 | 8,192 × 4,096 | 4.9 km | 200 | 50 MB |
| 4,096 | 16,384 × 8,192 | 2.4 km | 410 | 201 MB |
| 8,192 | 32,768 × 16,384 | 1.2 km | 820 | 805 MB |

The app keeps the memory of many layers low in the way of other paint programs. The tiles that you do not paint are on disk, and the screen uses a smaller copy. The active raster layer has its tiles at the full face size, in main memory and on the GPU. This is true only in the globe workspace, because the brush paints only there. In another workspace, the active layer gives back its tiles after a save, and it uses its copy as the other layers do. Before the app loads the tiles of the active layer, it compares the memory that they need with the memory that the system still gives the app. If the tiles do not fit, the app does not load them, and the status says so. Each other raster layer has a copy with a face of 2,048 pixels at most. A layer with a face of 2,048 pixels or less always shows in full detail. The copies of the visible layers on the GPU use 256 MB at most, with their pyramids. The copy of each visible image layer is in the same 256 MB. The pyramid of a layer uses a third of the memory of a dense copy of the layer. If they need more, each copy gets a smaller face. A hidden layer has no copy on the GPU. When you select a raster layer, the app loads its tiles from the working copy of the project, and the copy shows until the tiles are there. The globe and the flat view draw each visible raster layer at the detail of the screen, and a map frame and an export draw it at the detail of the page. Where the view or a frame needs more texels than the copy has, the app loads the tiles of the visible part of the world only. It uses the first level with at least one texel for each device pixel. The tiles come from main memory, or from the project file on a thread. The view and a frame show the copy until the tiles are there, and an export waits for them. After a move of less than one tile, the view keeps its tiles while the new tiles at the edge load. A layer below an opaque layer loads no tiles. The tiles of the view and of the frames use 256 MB of GPU memory at most. If they need more, the view and a frame on the screen take a coarser level, and an export renders the frame in strips.

You can change the face size of a raster layer later. The app then resamples each painted tile. For a smaller size, each new pixel is the mean of the pixels that it covers. For a larger size, the app interpolates between the pixels, which adds no detail. The change is one edit, so undo brings the old tiles back.

### Brush

The brush is a circle on the sphere with a radius in kilometers and a soft edge. It has four modes: raise, lower, smooth, and flatten to a level.

A pen sets the flow from pressure. A mouse uses a fixed flow. The brush size follows the zoom unless you lock it.

One stroke is one undo step. The step holds only the tiles that the stroke changed. With a project file, the step is in the undo log of the file. With no project file, the steps are in memory, and they use 256 MB at most. If a new step goes over that limit, the oldest steps go.

### Stepped preview

While you paint, a shader shows the heightmap as stepped tints. Each color stop of the layer is a value with a line. A band goes from one stop to the next, and each band has one color. A band owns the stop at its lower edge. This is the posterize and gradient overlay of the old workflow, live. Each raster layer has one of three displays. Bands fills each band with its color. Gradient blends from the middle of one band to the middle of the next. From an end of the range to the middle of the band at that end, the color does not change. Grey is the plain greyscale. On a height layer, sea level is a fixed stop, and it is a hard edge between the two bands next to it in the Gradient display.

The color stops and the display belong to the raster layer. The Style section of the panel of the layer shows them on a bar. A tap on the bar opens a page of the Layers panel with all the controls of the stops. The page has a vertical bar at the left, with the highest value at the top and a handle at each stop. At the right of the bar, each band has a row, with the highest band at the top. A row shows the color of the band, the value of its lower edge, and the line at that edge. All rows have the same height, the bar is as tall as the rows, and a line joins the handle of the lower edge of each band to its row. Thus many stops near each other on the bar still have large rows. The preview and the polygonize tool read the same stops, so the polygons match what you saw.

The app has one library of color ramps, and each part of the app that uses a ramp reads it. Each world can use the ramps. The library has the built-in ramps first and then the custom ramps. The built-in ramps are Viridis, Greens, Blues, Reds, Spectral, Earth, Bold, Pastel, and "Köppen climate". Bold, Pastel, and "Köppen climate" are qualitative: their colors are for classes with no order. A built-in ramp does not change. Each color of a ramp can have a label, for example a class name such as "Cfb". A ramp with labels gives its labels to the bands that it colors, as their names. "Köppen climate" has the 30 climate classes of Köppen and Geiger, with the colors of the common legend of Beck and others (2018), and each color has the code of its class as its label. The row "Color ramps" of the page of the color stops opens a page with the ramps. The row "Import ramp…" of the page adds a ramp from a legend image. A legend image is a row of blocks of color, from the lowest band to the highest, or a column of blocks from the bottom up. Borders, gaps, a margin, and a label above or below the blocks are not blocks. The import does not change a layer. The page lists the ramps, each with a bar of its colors. On a layer with a sea level, a ramp with no colors that are mostly blue is a land ramp, and it changes only the bands above sea level. A ramp with only such colors is a sea ramp, and it changes only the bands below sea level. Thus a land ramp and a sea ramp together color one layer. Each other ramp changes all bands. A tap on a ramp opens a card. On a layer with a sea level, the card has a choice of the bands that the ramp changes: all, the sea, or the land. It starts on the part that the colors give. If the ramp has as many colors as it has bands to change, the card applies the colors to the bands. Otherwise, the card offers two ways. "Fit" keeps the stops, and each band takes the color at its middle along the ramp. "Make" makes one band for each color, with even spacing. A ramp for all bands puts its first colors that are mostly blue below sea level. The card of a custom ramp also reverses the order of the colors and their labels, and it deletes the ramp. Its button "Edit labels…" opens the page "Labels", with a row for each color and a field for its label. The card of a built-in ramp with labels has the button "View labels", which opens the same page with the labels as text. In the desktop layout, the menu of a ramp has the same labels. The custom ramps are a text file in the folder of the app state.

Each color stop can also have a line, with a weight in points and a color. The color is a color that you pick, or the color of the band above the stop made darker by an amount that you set. The stops at the ends of the range have no line. The card of a band has a switch for the line at its lower edge, the weight, and the color. The globe and the flat map draw the line where the value crosses the stop, in the Bands display only. The line has the same weight on the screen at each zoom and on any shape of ground. The middle of the line is on the edge of the step, and the line goes around a sharp corner with a round end. An island or a pit that is smaller than one pixel in each direction has no line and no step color. Where the lines of two stops touch, each pixel shows the line that goes farthest past it. On a height layer, a line at sea level is the coast, and a line at another stop is a contour. Thus a height layer shows the coast and the contours with no vector step. The switch "Band lines" in the Style section of each raster layer hides all the lines of that layer, for example while you paint. The project keeps the switch of each layer.

The display smooths the field of a raster layer by the scale, so the detail follows the zoom. Each raster layer has a minimum feature size in points, from 0 to 8, and the default is 2. The app turns the size into a distance on the ground at the current zoom, and it smooths the field over that distance. A size of 0 shows the full detail. The fills, the lines at the color stops, and the snap target of a color stop all come from the same smoothed field, so they always agree. An exception is a raster layer that is not active, where the view shows detail tiles. There, the snap target comes from the copy, and it can be one texel of the copy away from the line.

The GPU keeps a pyramid of the field. A pyramid is a stack of levels, and each texel of a level is the mean of 2 by 2 texels of the level below. The shader reads the two levels that are nearest to the distance and blends them, so the detail changes with no jump while you zoom. A read near a face edge takes the texels past the edge from the next face, so the field has no seam. A brush stroke updates the levels under its texels in the same frame. For the snap target, the CPU makes the same levels with the same integer math, only for the blocks of texels near the pen.

The heightmap does not change, and the readout and the brush use the full detail. Each raster layer has a switch that turns its smoothing on and off on the globe and in the flat view, so you can paint one layer with the full detail in view. The project keeps the switch and the size of each layer. A map, a map frame, and an export always use the smoothing.

A height layer can show a hillshade over its colors. A hillshade is a shade of the slopes, with a light from one direction. North is the north of the world at each place, so the shade stays on the ground while you turn the globe. The shade blends with the colors in the soft-light mode. Flat ground keeps its color, slopes toward the light get lighter, and slopes away from the light get darker. The hillshade comes from the same smoothed field as the fills, in each display, on the globe and in the flat view. The rivers and the lines at the stops go over it. When you zoom out, the app makes the slopes steeper, so the relief shows at each zoom.

The hillshade has its own page in the Layers panel. The Hillshade row of the Style section opens the page, and the row shows if the hillshade is on. The project keeps each value of the page:

- A switch turns the hillshade on or off. The other controls show while it is on.
- The opacity is 0 to 100 percent. The default is 50.
- A switch turns the highlights on or off. Without the highlights, only the slopes away from the light change.
- A compass dial sets the direction of the light. North is 0 degrees, and east is 90. You drag the handle, or you tap a place on the dial. Near the 8 compass points, the direction snaps to the point. The default is 315, from the northwest.
- The light height is 5 to 85 degrees above the ground. The default is 45. A lower light gives a stronger shade.
- The relief makes the slopes 0.25 to 4 times as steep. The default is 1. It multiplies the change by the zoom.
- The slopes away from the light blend toward the shade color. The highlights stay grey. The default is black.

A final map can use the stepped raster with its lines as the topography, in place of the topography polygons. Polygonize is then optional.

### Toolbox

The toolbox is a searchable list of tools, open from every workspace. A tool takes one or more layers and a few parameters, and it writes a new layer. Polygonize is one tool in the list and not a button of its own.

Version 1 has six tools.

| Tool | Input | Output |
| --- | --- | --- |
| Polygonize | A raster layer, its color stops | Polygons, one for each step |
| Contour lines | Heightmap, interval | Lines with an elevation attribute |
| Smooth | Lines or polygons | The same layer with smoother outlines |
| Simplify | Lines or polygons | The same layer with fewer points |
| Dissolve | Polygons, an attribute | Polygons joined where the attribute is equal |
| Clip | A layer, a polygon or the extent of a map frame | The part of the layer inside the shape |

The output layer keeps a record of the tool, its inputs, and its parameters. When an input changes, the layer shows that it is out of date, and you run the tool again with one action.

All tools work on the sphere. They live in the core crates, so the command line can run them too.

### Polygonize

The polygonize tool traces the value of each color stop on each cube face, joins the outlines across face edges, and smooths them. It writes one polygon layer. It can also split the output at a value into two layers, for example Topography and Bathymetry at 0 m. Each polygon of a heightmap has an `elev_min` attribute, and a normal style rule colors it.

The polygons are an output layer of the toolbox. When the heightmap changes, the layer shows that it is out of date, and you run the tool again. A map can use the polygons, so topography stays vector in PDF and SVG. It can also use the stepped raster with the lines of its stops.

### Lines

A freehand line tool draws rivers, borders, and roads on the globe. The app smooths the stroke and stores it as a normal line feature. The tool draws in the active line layer, and each stroke is one undo step.

The path of the stroke is a curve through the pen samples, so a fast stroke has no corners. A Gaussian filter then takes away the shake of the hand. One Smoothing control sets the width of the filter, from 0 to 8 points on the screen. The default is 35 percent. A slow stroke gives a sample at each point, so its detail stays. The width is on the screen, so you zoom in to draw finer detail. The ends of the stroke stay where the pen was.

A stroke that starts within 12 points of the end of a line in the layer extends that line. The line keeps its UUID and its attributes, and the filter reads the end of the line, so the joint has no kink. Each other stroke makes a new feature.

In a free part of the stroke, the app removes each vertex that is less than 0.1 points from the simpler line. Where the line crosses the 180 degree meridian, it has two parts. One part ends at 180 and the next part starts at -180, at the same latitude. Two vertices of a part are at most 45 degrees of longitude apart, so a renderer in longitude and latitude draws each step the short way. Where a line goes over a pole, it has two vertices at the pole, with the longitude of each side. The globe draws each step as a great-circle arc.

### Terrain fit

The line tool has a terrain fit for roads. You draw a rough road between two places, and the app moves the line onto the path of least effort over the ground. You choose the ends and the route, and the app only refines your line. The fit runs when the pen lifts. The result is a normal line feature in the active line layer, with the smoothing of the line tool, and the stroke is one undo step. A later change to the terrain does not move a road.

The fit uses the first height layer of the project. With no height layer, the switch is disabled. The search is A* (a shortest-path search) on the texels of the cube map, in a corridor around the stroke. The corridor keeps the search fast, and it keeps the road near the route that you drew. Each texel has 16 neighbors: the 8 texels around it and the 8 texels at a knight move. A neighbor across a face edge is on the next face, so a road has no gap at a face edge or at 180 degrees.

The cost of a step is its length times a slope penalty, plus a penalty for the distance from the stroke. A step with a grade above 10 percent is not allowed. If no path below the limit exists in the corridor, the search runs again without the limit. A step from land into the sea or into a river has a fixed cost, so the road crosses water at a narrow place. A step along a line of the same layer costs half as much, so a new road joins the roads that exist. After the search, a pass replaces parts of the path with straight lines that cost almost the same, so the road does not zigzag.

The Balance slider sets the balance between the sketch and the terrain. Toward the terrain end, the corridor is wider and the distance from the stroke costs less. At the sketch end, the result is the same as the line tool with the fit off. The ends of the stroke use the snap service, so a road can start at a city or at the end of another road. A stroke that starts at the end of a line in the layer extends that line. The settings are not saved in the project.

### Polygons

A freehand polygon tool draws forests, deserts, lakes, and other areas on the globe. The tool draws in the active polygon layer. Each stroke makes one new feature, and each stroke is one undo step. The stroke has the smoothing of the line tool. It uses the snap service, so a part of the outline can trace a coast or a border.

The short arc of a great circle between the two ends of the stroke closes the ring. Each new edge gets a vertex at each degree of arc, so the flat map draws the same shape as the globe. Where the ring crosses itself, the polygon holds each area that the ring goes around. The area outside is the largest area between the parts of the ring, so the polygon has no holes. Two areas that touch at one point are two polygons of the feature.

Where the ring crosses the 180 degree meridian, the feature has a polygon on each side, with an edge along the meridian. A ring around a pole goes along the meridian to the pole and then along the pole. Each ring is closed and goes counterclockwise in longitude and latitude, and no two of its edges cross.

The tool has three modes: New, Add, and Subtract. New is the default, and in New each stroke makes a new feature. In Add and Subtract, the stroke closes into a ring as in New, and its area changes polygons that exist. The stroke snaps and traces as in New, so a part of the new outline can follow a coast.

- Add joins the area of the ring to one polygon of the layer: the first polygon that the stroke reaches. A stroke that starts inside a polygon, or within 12 points of its outline, reaches that polygon first. A stroke that overlaps no polygon changes nothing. Ground between the stroke and the polygon joins only where it is inside the ring.
- Subtract cuts the area of the ring out of each polygon of the layer that the ring overlaps. A cut through a polygon leaves one feature with two polygons, and a cut inside a polygon leaves a hole. A cut that covers a whole feature deletes the feature.

The outlines of the feature and the ring divide the sphere into areas, and the result is a set of these areas. Thus the result is valid on the sphere, also across the 180 degree meridian and around a pole. The stored vertices of the old outline do not move, and the feature keeps its UUID and its attributes. A hole is a ring of its polygon, and each ring goes counterclockwise in longitude and latitude. Each stroke is one undo step.

On the iPad, the mode cell is the first control cell of the polygon tool. It shows the icon and the name of the mode, with a small triangle in its corner, as the Sculpt cell does. A tap or a hold opens the list of the three modes next to the cell. A tap on a mode chooses it and closes the list, and a tap outside the list closes it. On the desktop, the tool bar has the three modes. Shift during a stroke chooses Add for that stroke, and Option chooses Subtract. The mode is not saved in the project.

### Points

The point tool places cities, landmarks, and other named places in the active point layer. A tap of the pen or a click of the mouse places one point, and a finger turns the globe. The point snaps to the targets of the snap service. A point that snaps to a vertex gets the stored position of the vertex.

A new point, line, or polygon gets the default value of each field, and it becomes the selection. You enter its attributes in the inspector, so you can name a town, a river, or a country when you draw it. No card and no window opens over the canvas.

When the inspector is open, it shows the new feature. The toggle "Focus new features" is in the title row of the inspector, and it is off at the first start. While it is off, the inspector does not ask for a value. A new feature takes the focus away from the field that has it, so the keyboard goes away. While it is on, a new feature takes the focus in the field that you edited last in its layer, or in the first field. The next tap of the point tool, or the next stroke of the line tool or the polygon tool, places the next feature, so ten points take ten taps and ten names. The app keeps the toggle with the settings of the tools, and the project file does not hold it. Return goes to the next field, and on the last field it ends the edit. The feature and the values that you type before the next feature are one undo step. Undo, a change of the tool, a change of the layer, and a change of the selection end the edit first. When the inspector is closed, nothing opens. A stroke that extends a line or reshapes a feature makes no new feature, so it does not change the selection or the inspector.

The app does not know the height of the on-screen keyboard. On the iPad, it takes the top of the keyboard at 45 percent of the screen height in landscape, and at 62 percent in portrait. On a compact screen, the keyboard is 336 points high, with the bottom band. While a field has the focus, the keyboard is up. If a new point is under the inspector, or under the keyboard, the globe turns, so the point is in the free part of the canvas. When the keyboard comes up, the globe turns again if it must.

### Measure

The Measure tool measures a path on the world. It works on the globe, in the flat view, and in the map frames of the Atlas, and it does not change a layer. A tap of the pen, a click of the mouse, or a tap of one finger adds a point to the path, and a drag turns the globe or moves the page. A point snaps to the targets of the snap service when Snap is on. In a map frame, the targets are the vector layers that the map shows, and the color stops are not targets.

Each segment is the short arc of a great circle, with a vertex at each degree of arc, as in the polygon tool. A label at the middle of each segment shows its length. The readout shows the length of an open path. A tap on the first point of a path with three or more points closes the path, and so does Return on the desktop. The readout then shows the perimeter and the area, on a sphere with the radius of the world. The area is the smaller of the two areas that the path divides the sphere into. A closed path that crosses itself shows its perimeter and no area. The lengths and the areas use the display units of the world. A tap after the path is closed starts a new path.

In the Atlas, the path shows in each map frame of the page, cut at the frame shape. A path can cross from one frame to another, because all the points are in longitude and latitude.

A measurement is temporary, and the project file and the undo log do not hold it. While Measure is the tool, undo and redo act on the path and not on the project. A new point, the close of the path, and "Clear path" are each one step. A new change empties the redo steps. A change of the tool, a change of the workspace, a change of the page, and "Clear path" clear the path. A change of the tool, the workspace, or the page also clears the undo steps of the path. A change of the view, of the layer, or of the radius does not clear it, and the values follow the radius and the units.

The math is in `vale-sphere`, and the area and length expressions use the same functions.

### Select

The Select tool selects features on the globe and in the flat view. The Select tool of the Atlas workspace also selects features, in an entered map frame, and the two tools have one selection. The active layer is the layer that is selected in the Layers panel. By default, the tool selects in the active vector layer only. A hidden layer has no selection. A tap of a finger, of the pen, or of the mouse selects one feature, and a tap on empty ground clears the selection. A drag of the pen or of the mouse selects the features in a box. A drag of one finger turns the globe, and two fingers pan and zoom, as in the other tools.

A finger that holds still on the canvas for 0.3 seconds acts as Shift until it moves or lifts. It does not turn the globe while it holds. With Shift, a tap adds a feature to the selection, or takes it out if it is selected, and a box adds its features. A tap with Shift on empty ground changes nothing. Two fingers that come down together are not a hold, so the tap of two fingers stays undo. On the desktop, a click with Shift adds or takes out, and a drag with Shift still turns the view. Add in the controls of the Select tool makes each tap and each box act as Shift, for one hand.

With two or more features selected, a tap on a selected feature makes it the key feature, and the selection stays. To select one of the selected features alone, you clear the selection first. The key has a wider outline in the accent color, on white. A command that needs one feature to act on the others uses the key. A selection that loses the key has no key.

A tap hits a point or a line within its reach on the screen: 22 points for a finger, 12 points for the pen, and 8 points for the mouse. A finger thus has a target of 44 points. The nearest point or line wins. If no point or line is in reach, the polygon under the tap wins. A feature on the far side of the globe is not hit.

A box selects a feature if a vertex of the feature is in the box, if an edge crosses the box, or if the polygon holds the box. The selection shows in the accent color: a ring around each point, a wide line on each line and each outline, and a handle at each end of a line. A change of the tool keeps the selection, and the selection shows in each tool. Deselect in the tool column clears it in each tool, and so does Deselect in the tool bar on the desktop. In the flat view, the selection shows, and the vector layers show their fills and their strokes.

Selectable in the controls of the Select tool opens a list of the layers that the tool selects in. The list has "Active layer" with the name of the active layer, "Select all", "Deselect all", and a row with a check for each vector layer, top first. "Active layer" is the default, and a mark shows on it while it is on. A tap on a layer row checks the layer or clears its check, and the tool then selects in the checked layers. "Select all" checks each vector layer, "Deselect all" clears each check, and a tap on "Active layer" goes back to the active layer. The list stays open while you check layers, and a tap outside it closes it. The two workspaces have one list, and the project does not save it. On the desktop, Selectable is a menu in the tool bar with the same rows.

With checked layers, a tap selects the nearest feature of the checked layers that show, and a box selects the features of all of them. If two features are at the same distance, the top layer wins. A selection can thus hold features of more than one layer. A selection in one layer makes that layer the active layer, and a selection in more than one layer keeps the active layer.

A pen drag or a mouse drag that starts on a point of the selection moves that point. The move is one undo step when the pen or the mouse comes up. The tool moves points only. Lines and polygons change in vertex editing.

A selection opens nothing over the map. The inspector shows the attributes of the selection. It follows the selection in each tool, so it always matches the highlight on the canvas. With one feature, the inspector has a field for each attribute, in a column. A value that is not of the field type has the warning color, and a change of a field is one undo step when the field loses the focus. With more than one feature of one layer, the inspector shows the count above the fields. A field whose value is the same in each feature shows that value. A field whose values differ is empty and shows "Mixed", and it changes nothing until you edit it. An edit of a field gives the value to each selected feature in one undo step. With features of more than one layer, it shows the name of each layer and the count of its features. With no selection, it shows "Select a feature to see its attributes." After you edit a field, the next feature that you select in the layer gets the focus in the same field, so you can tap one river after another and type each name. An empty selection, a change of the layer, and a change of the tool end this. The inspector also has "Show in table", which opens the attribute table of the layer at the first selected row.

If other features of the layer have values in a field, the field has a button at its right end. The button lists the values, each one time and in order, with a mark at the current value. A tap on a value puts it in the field in one undo step, so a town size or a road type keeps one spelling. A field with more than 50 different values has no button. On the iPad, the button opens a menu below the field, or above it if the screen has no room below. The menu shows five rows and scrolls, and a tap outside it closes it. On the desktop, the button opens a menu.

On the iPad, the inspector is the Attributes panel, a pane of the dock. While Select is the tool, the tool column has Selectable and "Delete selection", which deletes all selected features in one undo step, in each layer. It is off with no selection. The column also has "Merge…", which is off for a selection in more than one layer, and "Subtract". The order is Selectable, Add, "Delete selection", "Merge…", and "Subtract". On the desktop, the Edit menu has "Delete selection", "Merge…", and "Subtract". The inspector is a panel at the right, and ⌘I and the View menu show and hide it. Delete and Backspace delete the selection, and Esc clears it.

The Atlas workspace has the same inspector. On the iPad, the Attributes tile of the Panels menu opens it as a pane of the dock, beside the panes of the selection. On the desktop, ⌘I shows it. An edit changes the world, so each map shows it.

### Attribute table

The attribute table shows the features of a vector layer as rows, with a column for each field. On the iPad, the row Features on the page of the layer opens it. In the Atlas workspace, the row Features on the page of a vector layer in the Layers tab of a frame opens it. On the desktop, "Open attribute table" in the context menu of the layer opens it, and so does "Open attribute table" in the Layers tab of a frame. The dock follows a change of the active vector layer. The project does not save the table.

Above the rows are the filter field, with the count of the rows at its right end, and the control "All | Selected". The filter is an expression, and the table shows the rows for which it is true. A filter with an error shows no rows, and the text of the error. With Selected, the table shows only the selected rows that the filter shows. All is the default. A tap on the header of a column sorts by its field, up and then down, and a third tap ends the sort. Text sorts with no regard to case, and an empty value is last in both directions. The table builds its rows again only when the features, the sort, the filter, or the shown selection change. It draws only the rows that show, so a layer of 50,000 features scrolls, sorts, and filters with no delay.

The selection of the table is the selection of the Select tool. A tap on a row selects its feature, and the globe, the flat view, and the map frames show it. With Selected, the table shows the selected rows of its own layer. A change of the selection on the globe scrolls the table to the first selected row of its layer. On the desktop, a click with Command adds a row or removes it, and a click with Shift adds the rows between it and the last selected row. A new feature of the line tool, the polygon tool, or the point tool is the selection.

A tap on a cell of a selected row edits the cell, with the same field and the same check of the value as the card of the selection. If more than one row is selected, the edit sets the field of each selected row. Return or a change of the focus ends the edit, and Esc drops it. The edit is one undo step, and a value that is not a value of the type of the field changes nothing.

On the iPad, the table is the page Attribute table of the layer in the Layers panel, or in the Layers tab of a frame in the Atlas workspace, and Back goes to the page of the layer. In the Atlas workspace, "Show in table" opens the Layers tab of the selected frame, or of the top frame of the page whose map shows the layer. The page fills the pane, and only the rows scroll. While the page shows, the dock is at least 480 points wide if the screen has room. The Attributes pane can show in the dock at the same time. While a cell has the keyboard, the rows scroll as far as they must to keep the cell above the keyboard, and the dock does not move. On a compact screen, the page is in the sheet. The rows scroll in both directions, and the header moves sideways with them, so a drag shows the fields that do not fit. Each row and each header is 44 points high. On the desktop, the table is in a dock below the canvas.

### Reshape

Reshape redraws a part of the outline of a line or a polygon with a stroke of the line tool or the polygon tool. The Reshape switch of the tool turns it on. With Reshape on, a stroke that starts within 12 points of the outline of a feature in the active layer reshapes that feature. The nearest outline wins. A stroke that starts at the end of a line still extends the line, and any other stroke draws a new feature. Reshape needs no selection. Reshape works in the New mode of the polygon tool only.

- On a polygon, the stroke ends within 12 points of the same ring. The ring then has two possible shapes, one with each part of the old ring between the ends of the stroke. The shape with the larger area stays. A stroke that crosses itself or the outline gives the simple rings of the area, as in the polygon tool. A hole stays in the polygon that holds it. A stroke that ends away from the ring changes nothing.
- On a line, a stroke that ends on the line takes the place of the part between its ends. A stroke that ends away from the line takes the place of the rest of the line, toward the end of the line that is nearer to the end of the stroke.

The stroke snaps and traces like the other strokes of the tool, but it does not snap to or trace the feature that it reshapes. While the stroke draws, the outline of the feature shows in the accent color, and the stroke of the polygon tool does not close. The stored vertices of the old outline outside the reshaped part do not change. The parts of a polygon on the two sides of the 180 degree meridian are one outline for the reshape. Each reshape is one undo step, and the feature keeps its attributes.

On the iPad, the controls of the line tool and of the polygon tool have the Reshape button after the Snap button. The Brush panel has the Reshape switch. On the desktop, the tool bar has the Reshape check box. The switch is not saved in the project.

### Split

Split cuts lines and polygons along a stroke. One country becomes two, or a road becomes two roads. Split is a tool of the Vector cell for line layers and polygon layers. The stroke splits each feature of the active layer that it crosses from side to side. A selection does not limit the split. The stroke draws as a thin white sketch line, not in the style of the layer.

- A polygon becomes one feature for each area between its outline and the stroke. The parts share the vertices of the cut, so they have no gap and no overlap.
- A line becomes one feature between each two places where the stroke crosses it. A stroke that touches a line and turns back does not cut it.

A stroke that ends inside a polygon, or that does not reach a line, changes nothing. The stroke goes on for 12 points past each end, so an end near an outline crosses it. A cut that leaves a part smaller than 1 square point, or a line shorter than 3 points, joins that part to the part next to it. A part of a feature that the stroke does not cut, for example an island or a hole, goes to the part that holds it, or else to the largest part.

Each part is a new feature with a new UUID and the attributes of the old feature. The parts take the place of the old feature in the draw order. The parts become the selection, so the cut shows at once. A stroke that splits nothing leaves the selection as it is. The cut is on the sphere, so a split is correct across the 180 degree meridian and near a pole. The stroke snaps and traces as the other strokes do, so a split can follow a river or a ridge. Each split is one undo step.

On the iPad, the controls of Split have the Smoothing slider and the Snap button. On the desktop, the tool bar has a Split button next to the tool that draws.

### Subtract

Subtract cuts one polygon out of others. For example, a new province cuts its area out of its neighbors, so the borders meet with no overlap. The mode Subtract of the polygon tool cuts the area of a stroke, and this command cuts the area of a polygon.

Subtract is a command of the Select tool. The key feature of the selection cuts, and it does not change. The cut changes each other selected polygon that the key overlaps, in any layer. The polygons can be in one layer. A polygon that is not selected does not change. The new outlines use the vertices of the key, so the two share the border. A polygon that the cut covers goes away, and it leaves the selection. The cut is on the sphere, so it is correct across the 180 degree meridian and around a pole. Each cut is one undo step.

"Subtract" is off unless the key is a polygon and another polygon is selected.

### Merge

Merge joins the selected features of one layer into one feature. Two provinces become one kingdom, or two parts of a river become one river.

- Polygons become one polygon. Polygons that touch or overlap lose the border between them, and polygons that do not touch become parts of one feature.
- Two lines that share an end become one line. A line turns around if it must. Lines that do not share an end become parts of one feature.
- Points become one feature with each point.

Merge asks which feature keeps its attributes. If all the selected features have the same attributes, Merge does not ask, and the largest feature stays. The list names each feature by the label text of the layer, or else as "Feature" and a number. The largest feature is first. The order of a box selection does not show, so the app does not take the first feature. The merged feature keeps the UUID and the place in the draw order of that feature, and it becomes the selection. The merge is on the sphere, so it is correct across the 180 degree meridian and around a pole. Each merge is one undo step.

On the iPad, the card of the Select tool has "Merge…", after "Delete selection". The list opens at the right of the card, and a touch outside the list closes it. On the desktop, "Merge…" is in the Edit menu, and the list is in a window. "Merge…" is off unless two or more features of one layer are selected.

### Vertex

Vertex edits one line or polygon by its vertices. Vertex is a tool of the Vector cell for line layers and polygon layers, and A chooses it on the desktop. A tap on a line or a polygon of the active layer selects it, and its vertices show as handles. A handle is small on the screen, and it takes a touch of 44 points with each pointer. Of two handles in reach, the nearer one wins.

- A drag of a handle moves its vertex. A pen, a finger, and the mouse drag a handle. A finger that starts away from a handle moves the view.
- A drag of a selected handle moves all the selected vertices. Each of them turns on the sphere by the same rotation as the dragged vertex, so the shape keeps its form. Only the dragged vertex snaps. A drag of a handle that is not selected moves that vertex alone.
- A tap on a handle selects its vertex. A tap on an edge adds a vertex there and selects it. A tap on empty ground clears the selected vertices, and a second tap clears the selection.
- A drag of the pen or the mouse that starts away from a handle selects the vertices in a box.
- "Delete vertex" deletes the selected vertices, and so do Delete and Backspace on the desktop. A line keeps two vertices, and a ring keeps three.
- "Smooth vertices" smooths the part of the line or the ring between the selected vertices, with the smoothing of the line tool. On a ring, the part leaves out the longest run of vertices that are not selected. The vertices outside the part do not move.

A moved vertex snaps to the targets of the snap service, and the snap switches apply. A vertex that snaps to a vertex takes its stored position. A vertex is known by its stored position. A trace copies the vertices of its target, so two polygons that share a border have their vertices at the same positions. With "Move shared vertices" on, a move, an add, or a delete changes each feature of the layer that has a vertex at the same position, so the border has no gap and no overlap. The moving vertex and its edges are then not snap targets. The switch is on by default, and the project does not save it. A move that makes a ring cross itself makes simple rings, as Reshape does.

The edit is on the sphere, so it is correct across the 180 degree meridian and near a pole. Each move, add, delete, and smooth is one undo step.

On the iPad, the controls of Vertex are Snap, "Move shared vertices", "Delete vertex", "Smooth vertices", and the Brush button. The Brush panel has the Smoothing slider and the snap settings. On the desktop, the tool bar has a Vertex button, and its options have the same controls.

### Attribute schema

The panel of a vector layer lists the fields of the layer, each with its type. "Add field…" opens a page with the name, the type, and the default value of a new field. The name has the keyboard focus, so the on-screen keyboard opens. "Add", or Return in the name, adds the field. A tap on a field opens its page. There you change the name, the type, and the default value, and "Delete field" removes the field.

A field name is not blank, and it is not `fid`, `geom`, or `uuid`. No two fields of a layer have the same name, and the check ignores the difference between capital and small letters. A name that breaks these rules has the warning color, and "Add" is off. A default value that is not a value of the type also has the warning color, and "Add" is off.

A new field is null in each feature, and each new feature gets the default value. A change of the type converts each value and the default value. A value that does not convert is null. A new point layer has a `name` text field, and its label text is `name`. A rename of a field changes each expression of the layer that uses the field: the filters and the properties of the rules, the label text, the priority field, and the label classes of the maps and the map styles. Each change of the schema is one undo step, and the project saves at once.

### Snapping and tracing

The vector tools share one snap service. A snap moves a position to the nearest target within the snap distance. A trace makes a freehand stroke follow a target. The targets are the vertices and the edges of the features in each visible vector layer. The color stops of each raster layer that the globe shows in the Bands display are targets too. A vertex wins over an edge or a color stop. Of an edge and a color stop, the nearer one wins. Later targets are the ridges and valleys.

The snap distance is in points on the screen, from 4 to 32, and the default is 12. It is the same at each zoom. The start and the end of a stroke snap to a target.

When the pen comes within the snap distance of an edge, the stroke locks on and follows the line or the ring of the target. The trace only moves forward along the target, and it can go on past a cut at the 180 degree meridian. When the pen moves more than two times the snap distance away, the stroke is free again. A trace that is shorter than 8 points becomes free stroke again, so a stroke that crosses a line does not follow it.

The traced part goes from the first to the last pen sample within a quarter of the snap distance of the target. It has a copy of each stored vertex of the target, so the two features share the border exactly. The app does not smooth the traced part. Before and after the traced part, the stroke blends from the pen to the target, so it meets the target at the angle of the pen. Each free part has its own smoothing, and its ends stay on the target.

A stroke that starts at the end of a line in the same layer extends that line, and it does not trace that line. A stroke from the end of a line extends it also with Reshape on. The target shows a highlight in the accent color while a stroke snaps or traces. Before a stroke, a pen that hovers or a mouse shows the point where the stroke will start: the end of the line that it extends, or the snapped position.

The target of a color stop is the line where the field of the layer crosses the value of the stop. Each stop between the two ends of the range is a target, with a line or without one, because it is the edge of a step. The target comes from the same smoothed field at the current zoom as the steps and the lines. The app reads the field only near the pen.

A position snaps to the nearest point where the field crosses a stop. A trace walks along the line in steps of half a point, and each step goes back onto the line. The field has no seam, so the trace has no gap at a face edge or at a cube corner. The trace of a color stop has no stored vertices, and the app removes each vertex that is less than 0.1 points from the simpler line.

The line tool, the polygon tool, the point tool, and Vertex have a Snap switch on the brush card. The line tool and the polygon tool also have the Reshape switch, and the line tool has the Fit switch of the terrain fit. The sheet has the Snapping switch, a switch for each target type, a switch for the color stops of each raster layer, and the snap distance. The settings are not saved in the project.

The service has two parts. A position snap gives the snapped point, the feature, and the stored vertex. A tracer takes the pen samples of a stroke and gives free parts and traced parts. Point placement, vertex editing, and the polygon tool use the same two parts.

### Import

You can import an equirectangular heightmap that you painted before. The app copies it into the cube map.

### Pen and iPad

The drawing tools are designed for a pen: pressure, hover preview of the brush, and palm rejection. On desktop that is a graphics tablet. On iPad it is Apple Pencil.

On iPad, winit 0.30 gives 120 pen samples per second, no hover, and no tilt. A UIKit gesture recognizer on the view of the app reads the pen below egui. It reads the coalesced touches (the extra pen samples that iOS collects in each frame, 240 per second), the tilt, and the hover. It sends them to the canvas, and it does not take the touches from winit. The canvas reads the pen from that recognizer, and egui handles the pen only on the panels. Fingers come through egui. While the pen is down, each other touch is a palm.

The path of a stroke is a curve through the pen samples, so a fast stroke has no corners.

A double tap or a squeeze of the Apple Pencil switches between the current tool and the last tool. Each tool of the tool column is a tool of the switch, and each brush mode counts as a tool. Thus Raise, then Smooth, then a double tap gives Raise again. The app follows the Pencil setting of the system. If the gesture is off or has another action, the app does nothing. With the setting "Switch between current tool and eraser", the switch goes to the opposite mode where one exists. Raise and Lower switch with each other, and the Noise mode swaps its Raise and Lower values. In the other tools and modes, the switch goes to the last tool. If the last tool cannot work in the active layer, the switch does nothing.

Each tool keeps its own settings. Each brush mode keeps its size, size lock, hardness, flow, and strength, and a choice of the mode brings them back. This is true for a choice with the tool column, with the list of a cell, and with the Pencil. A mode that you did not use yet has the settings of a new brush. The other brush settings belong to one mode each, so they stay with that mode. The pressure settings stay shared, because they belong to the hand and the pen. The Line tool and the Polygon tool each keep their own Smoothing. The snap settings stay shared, because the vector tools share one snap service. The app keeps the settings of each tool in the file `tools.txt`, in the folder that holds the state of the last run. Thus they are the same after the app closes. The project file does not hold them.

- A color of a vector style or of the atlas has an opacity, which is the alpha of the color, from 0 to 100 %. Examples are a fill, a stroke, the text and the halo of a label, a leader line, the graticule, the neatline, the border, the furniture, and the layout grid. Its color picker has an opacity strip below the hue strip, which shows the color from transparent to opaque over a checkerboard. Its hex field shows `RRGGBB` for an opaque color and `RRGGBBAA` for a color with alpha, and it takes both. The swatch of a color row shows the alpha over a checkerboard. On the desktop, the color button edits the alpha too. The colors of the raster bands, the contour lines, the hillshade, and the paper are opaque, and their pickers have no opacity strip. The eyedropper keeps the alpha. The alpha of a stroke applies one time to the whole stroke, so a corner, a crossing, or an overlap of two dashes is not darker. The dabs of a brush stroke build up first, and then the alpha applies.
- Each color picker has an Eyedropper button at the right of the hue strip. A tap on it starts the eyedropper, and a card at the top shows "Touch a color to pick it." and Cancel. The eyedropper picks the pixel that you see, so it includes the hillshade, the blending, and the UI. While it is on, a touch, the pen, or the mouse goes to no tool, card, or panel. While the finger is down, a loupe above the finger shows the color under it. When the finger lifts, the picker takes that color and the eyedropper ends. Cancel ends it with no change.
- A setting that you judge by eye is a slider, for example the brush size, the flow, or an opacity. A setting that is a quantity is a stepper, for example a height in meters, a width in points, a count, or the seed.
- A slider track, the value box of a slider, and a stepper are 36 points high. The track fills up to a flat handle.
- A touch on the track of a slider does not move it. A drag moves the value by the distance of the drag. If the finger moves away from the track during the drag, the value moves more slowly: at half speed from 60 points, at a quarter from 120 points, and at an eighth from 180 points.
- During the drag, a bubble next to the panel, at the height of the row, shows the value and the speed. It stays in its place during the drag. The brush size also shows the brush as a circle at the center of the screen, at its size on the globe. The thumb stops at the default value of the setting and at each named mark.
- A stepper is one control with a minus button, the value, and a plus button. A button that you hold repeats. If the range of the setting spans many orders of size, the buttons go through 1, 2, 5, 10, 20, and so on.
- A tap on the value of a slider or a stepper opens the keypad in a card next to the panel, at the height of the row, so the rows do not move.
- The bubble and the card of the keypad are over the globe. Each one is at the right of the panel, past any other panel there, else at the left, else above the panel, as for a sheet. With no place over the globe, the card floats over the panel below the row, and its blur shows the panel. The typed value takes effect when the keypad closes, and it is clamped to the range of the setting.

The core crates have no UI dependency, so both platforms share them. The shell is egui on both platforms. The crate `vale-globe-proto` checked how well egui handles pen input and touch on iPad, and the section "Globe prototype" gives the results.

#### Dock and Panels menu

The dock is one card on the right edge. It holds the open panes in one column. Below each pane is a bar 24 points high. Its touch area is 44 points high, and the last bar has 10 more points below it, so its touch area is in the dock. A pane holds one or more panels as tabs. Two panes are never side by side. With no pane open, the dock is not there.

Each pane has a header with its tabs or its title, a chevron, and the action of its panel. A tab shows the icon of its panel, and the open tab also shows the name. A pane with one tab shows the icon and the name as its title. In a dock 420 points wide or more, each tab shows its name. If the names do not fit, the tabs show only their icons. A row that opens a page, such as the page of a layer, shows the page in the same pane, with a back row at the top.

These rules apply to the dock:

- A new pane opens at the bottom of the dock.
- A pane stays open until you close it. It keeps its place, its height, and its tabs. A tap on the canvas closes no pane.
- A long press on a tab or on the title opens a menu with "Close" and the name of the panel, and "Collapse pane" or "Expand pane". With more than one tab, the menu also has "Move to new pane".
- A pane can fold to its header, with no body. A tap on the open tab, or on the title of a pane with one tab, folds the pane or opens it again. So does a tap on the chevron at the left of the action of the header. The chevron points down while the pane is open, and right while it is folded. A tap on another tab shows that tab and opens the pane. A folded pane is as high as its header, so the other panes get the room, and its bar does not change its height. A selection opens a folded pane only if it opens the panel. A panel that you open from its tile opens its pane. The sheet of a compact screen shows the pane open.
- A selection opens one pane at most, and it never closes a pane. In the Atlas workspace, a frame opens Properties if no frame panel is open, a tap on the paper opens Pages, and a furniture item opens Properties. A map from a region opens Projection in place of Properties.
- A selection does not change the tab that shows in a pane, and it does not show a hidden dock. A panel that you open from its tile shows the dock.
- A selection does not open a panel that you closed. Only its tile opens it again. After that, a selection can open it again.
- A pane with nothing to show shows a hint, for example "Select an item to see its settings."
- A drag of the bar below a pane changes the height of that pane. A pane grows into the free room of the dock first, and then takes room from the panes below it. A pane that gets shorter gives its room to the panes below it that scroll. A pane is never taller than its content.
- A double tap on the bar below a pane makes the pane as tall as the dock allows. The other panes get as short as they can.
- A drag of the empty part of a header moves the pane to another place in the column.
- A drag of a tab onto the tab row of another pane adds it as a tab. A drag of a tab to a place in the column makes it a pane of its own.
- A drag on a header that starts sideways to the right moves the whole dock with the finger. The swipe follows the touch events in their order, so a quick flick that starts and ends between two frames also counts. At the release, the dock collapses as an overlay sidebar of UIKit does: the speed of the finger in its last 0.1 seconds gives the distance that a throw would coast, with the deceleration rate 0.998 of UIKit. If the dock would then be past half its width, it collapses. Else it slides back. A drag that starts up, down, or to the left moves the pane or the tab.
- The handle "Dock width" at the middle of the left edge of the dock changes its width. Its grip is on the edge, on a dark capsule. Its touch area is 44 by 120 points on the edge, 20 points of it in the dock, as the resize handles of iPadOS are. It takes only a drag, so a tap there still reaches the row of the pane below it. A touch on the dock does not cover the grip. The width goes from 300 to 520 points. During the drag, a label shows the width. The dock is 340 points wide at first.
- The dock is as tall as its panes, and it ends 8 points above the bottom band. If the panes do not fit, each pane that does not fit gets shorter and scrolls its content. A pane with content that fits keeps its height.
- A pane is never shorter than its header and two rows. If the panes still do not fit, the last panes join the last pane that fits, as tabs. When the room is there again, they are panes of their own again.
- The dock can collapse. It then slides off the right edge in 0.25 seconds, and it keeps its layout. The Dock button in the top row collapses the dock and shows it again. The button has the accent color while the dock shows, and it is off while the dock has no pane. A swipe to the right on a header, and a drag of the width handle 40 points past the narrowest width, also collapse the dock.
- A slim tab at the middle of the right edge shows a collapsed dock again, with a tap or a drag to the left. A panel that opens also shows the dock.
- The dock floats over the canvas. The globe and the flat map do not move when the dock shows, hides, or changes its width. At 600 points or more, a page fits at the left of a dock of the default width, 340 points, and its width handle, whether the dock shows or not. This is the place where a page opens, and where a double tap fits it.
- Each workspace has its own dock. The file `panels.txt`, in the folder that holds the state of the last run, keeps the open panes, the folded panes, and the width of each dock. It also keeps the arrangement of the panels of a frame, the collapsed state, and the panels that you closed. The project file does not hold them.

The Panels button opens the Panels menu below the top row. The menu has a tile for each panel of the workspace. A tinted tile is an open panel. No tile is off. A tap on a tile opens the panel, shows it if it is a tab behind another tab, or closes it if it shows. Below the tiles, "Close all" closes each pane. "Reset layout" closes each pane, sets the width to 340 points, and shows the dock. It also puts the arrangement of the panels of a frame back to the first one, and it forgets the panels that you closed. If a frame is selected, Properties then opens.

The World workspace has the tiles Layers, Attributes, Toolbox, and Brush. The Atlas workspace has two groups of tiles. The group Selection holds Properties, Projection, Layers, and Labels, and the group Atlas holds Pages, Attributes, and Brush. The section "Maps and the atlas" gives the panels of the Atlas workspace.

On a compact screen, the dock is the sheet. The sheet shows the pane of the last focus, with its tab row and a close button. A long press on a tab opens a menu with "Close" and the name of the panel. The sheet has no bars and no handle, and its tabs do not move.

## Styling model

A style is an ordered list of rules. Each rule has a filter, a scale range, and one or more symbolizers (instructions that draw a feature). This is the QGIS rule-based model, and it lets one style serve all maps.

A filter is an expression on attributes, for example `population > 50000 and kind = 'city'`. Each symbolizer property can also be an expression, so the line width of a river can come from a `flow` attribute.

The same expression language serves filters, style properties, label text, and the attribute table. `docs/EXPRESSIONS.md` has its grammar and its functions.

A rule draws a feature when its filter matches and the scale denominator is in its range. The lower limit is in the range, and the upper limit is not. Each rule that matches draws the feature, in the order of the list. The project stores the style of each layer as JSON with a version number, together with the label settings of the layer.

The style of a layer in the World workspace is the globe style. You edit it in the panel of the layer in the World workspace. The globe and the flat view draw it. It is also the start style of the layer in a new map. Each map holds a full style for each vector layer, raster layer, and image layer, with its own rules, filters, order, and symbolizers. A change to the globe style does not change a map, and a change to a map does not change the globe or another map. A new map copies the globe style of each layer. A new layer copies its globe style into each map with no map style and into each map style. In the Layers tab of a selected frame, the panel of a layer changes the style of the layer in the map of the frame.

The Style section of the panel of a vector layer lists the rules in draw order, with the first rule at the top. Each row shows the filter of its rule. "Add rule" adds a rule at the end and opens its page. The new rule has the symbolizers of the last rule, with the next default color of the layer kind. A tap on a rule also opens its page. The page has the filter, the scale range, the stroke, and the fill. The stroke has a color, a width, and a line type. The line type is solid, dashed, brush, or taper. A dashed line has a dash length and a gap length. A tapered line is narrow at its first vertex and has the full width at its last vertex, and its start width is a percentage of the full width. Only a line layer has the taper. In a PDF, a brush line is a raster image, and the other line types stay vector. The page of a point layer has the Marker choice: a shape or an SVG symbol. A shape marker has a Marker shape row and a size. The shapes are circle, square, diamond, triangle, and star. The size is the diameter of a circle and the width of the other shapes, in points. The Fill row of a shape marker opens the Fill page. The fill is solid, hatch, cross-hatch, or none. A hatch has an angle, a spacing in points, and a line width. The lines of a hatch have the color of the fill. An SVG symbol has a Symbol row, a size, a rotation, a field for the size, a field for the rotation, and a tint. The Symbol row shows the current symbol, and a tap on it opens the symbol page. The symbol page has a tile for each symbol of the project and the "Add symbol…" button, which adds an SVG file. A tap on a tile picks the symbol and goes back to the page of the rule. If the project has no symbols, the symbol page shows a hint and the button. A tap on "SVG symbol" opens the symbol page, and the shape stays until you pick a symbol. A field makes the property an expression on that field, and the value of the slider is the fallback. A tint replaces the colors of the symbol. A new symbol has no tint. The page of a polygon layer has a Scatter switch below the fill. The switch opens the symbol page, and the scatter starts when you pick a symbol. A scatter has a Symbol row, a size, a spacing, a size variation, a rotation variation, and a tint. The spacing is never less than the size. The filter has the segments Blocks and Code, which show the one stored text. In Blocks, the filter is "Match all" or "Match any" of a list of conditions. Each condition has a field chip, a comparison menu, its values, and a button that removes it. The comparisons follow the type of the field. A number has comparisons such as "is greater than" and "is between". A text has "contains", "starts with", and "is one of". A yes-or-no field has "is". The value of a text field comes from a menu of the values in the layer, with search. A number has the keypad, and a yes-or-no field has Yes and No. "Is between" takes two values, and "is empty" and "is not empty" take none. The field menu has the section Geometry below the fields, with the measures of the layer kind. A polygon layer has Area, Perimeter, Vertices, Parts, Latitude, and Longitude. A line layer has Length in place of Area and Perimeter, and a point layer has Vertices, Latitude, and Longitude. The measures take the comparisons of a number. A condition on Area, Perimeter, or Length has a Unit menu after the field chip, for example `area('mi2') > 10000`. "Add condition" adds a condition on the first field, or on the first measure if the layer has no fields. "Add group" adds a group. A group is "Any of" or "All of" its conditions, and it can hold groups. A part of the text that is not a condition shows as a red row, and a tap on the row opens Code. A filter with no conditions in its text opens in Code. Below the conditions, the line "Matches N of M features" has a meter. A blank scale limit means no limit. "Move rule up", "Move rule down", and "Delete rule" change the list. The map redraws during each drag of a color, a width, a length, a size, or an angle, and one drag is one undo step. In the desktop layout, the same controls are in the panel of the layer in the globe workspace and in the dock of the Atlas workspace. In the desktop layout, a list holds the symbols, and the "Add symbol…" button is next to it. If the project has no symbols, the list is off.

"Classify…" in the Style section opens the Classify form. The button "Replace rules" of the form replaces all rules of the layer with one rule for each class, in one undo step. A chip for each field and the Expression field give the values, so a class can come from an expression such as `area('km2')`. Numbers have three methods. Equal intervals gives classes of the same width. Quantiles gives classes with the same number of features. Natural breaks puts the class edges in the largest gaps between the values. The number of classes is 2 to 12, and the default is 5. Equal values stay in one class, so the form can make fewer classes. Each edge of a quantile or a natural break is the roundest number between the values on its two sides. The first class has no lower limit, and the last class has no upper limit, for example `area('km2') < 120`, `area('km2') >= 120 and area('km2') < 450`, and `area('km2') >= 450`. If features have no number, the rule "No value" takes them. Text gives one rule for each common value, at most 12, with the most common value first. Each other value that is a label of the ramp also gets a rule. The rule "Other values" takes the other values and the features with no value. The name of a rule is its range or its value. Each new rule has the symbolizers of the first rule, with the color of its class. The colors come from a ramp of the library, and the "Reverse colors" switch reverses them. The form starts on Viridis for numbers and on Bold for text. The row of the ramp opens the page "Color ramps", the same page as the page of a raster layer, with "Import ramp…". The card of a ramp has "Use", which picks the ramp and goes back to the form, and the buttons of the labels, the reverse, and the delete. A text class whose value is a label of the ramp takes the color of the label. Case does not count. The note above "Replace rules" shows the number of new rules and how many of them match a label, for example "5 rules · 3 labeled". If a class takes a label, each other class takes the next color that no label took. Otherwise, a qualitative ramp gives its colors in order, and another ramp gives even steps from its first color to its last color. For numbers, the "Vary width" switch steps the stroke width of a line or a polygon from the first class to the last class, and the "Vary size" switch steps the size of a point. The From and To fields give the values of the first class and the last class. In the layer panel of a map frame, the form is off. In the desktop layout, a "Classify…" section below the rules has the same controls and an "Import ramp…" button, without the step.

On a polygon layer, the "Neighbors differ" switch of the Classify form gives each polygon a color that no neighbor has. This is the usual way to color political borders. Two polygons are neighbors if they share a border. A border is a part of the boundary of one polygon that is within a tolerance of the boundary of the other polygon. The tolerance is 1/400 of the median perimeter of the polygons, so a small gap or overlap of hand-drawn borders is still a border. A border must be at least 4 tolerances long, so two polygons that touch only at a corner are not neighbors. The test uses points on the sphere, so a border on the antimeridian counts. The Colors field sets the number of colors, from 4 to 12, and the default is 5. The polygon with the most colors among its neighbors takes the next color (DSatur). Each polygon takes the free color with the least area so far, so the colors cover about the same area. If the polygons need more colors than the Colors field gives, the form adds colors. The form saves the colors as the numbers 1, 2, 3, and so on, in the whole-number field `color_group`. If the layer has a field of that name of another type, the form uses `color_group_2`, and so on. The rules are "Color 1", "Color 2", and so on, and "Other values" takes a polygon with no color, such as a new polygon. The field and the rules change in one undo step. The colors do not follow an edit, so after an edit you use the form again. The form starts on Bold. In a map frame, the rules go to the map of the frame, and the field goes to the layer. The field and the rules of the map change in one undo step. In the desktop layout, the Classify section has the same switch.

Each expression field helps you write the expression: the filter of a rule, the text and the filter of a label class, the Expression field of the Classify form, and the filter of the attribute table. On iPad, the label text, a filter, and a value each have their own editor. While a pane shows one of these editors, the dock is at least 460 points wide if the screen has room, and a sheet keeps its width. The filter field of the table is plain text. Below the field, a line shows the result for the selected feature of the layer, or else for the first feature: "Matches" or "Does not match" for a filter, the text or "No label" for a label text, and the value or "No value" for a value. If the text does not parse, the line shows the message of the parser. The preview uses the scale 1:1,000,000. In the desktop layout, the label text and a value are the same token fields with the desktop sizes, and an "Insert" menu above the field has the submenus Fields and Functions. The menu of a label text also has Geometry, with the measures of the layer kind. The menu of a value also has Variables, with the `@` variables. A submenu with no items does not show. In label text, `{` opens a completion list of the fields whose names start with the typed word, each with its value in the feature of the preview, of the text functions, and of the measures. In a value, a typed word opens the completion of the fields and the functions, and a word that starts with `@` opens the completion of the variables. Return inserts the highlighted item, Up and Down move the highlight, and Escape closes the list and keeps the typed text as text. In a value, Tab goes to the next slot. Backspace selects a chip, and a second Backspace deletes it. A drag of a few points moves a chip, and Command-X, Command-C, and Command-V cut, copy, and paste chips. A filter shows as a line of tokens with the match count below it, and a click on it opens the filter editor of the iPad in a popover. The filter field of the table is plain text with the "Insert" menu. Each desktop field shows the same line below it.

The label text of a layer is an expression, as the text of a label class is. Blank text gives no labels. On iPad, the Labels section of the layer panel has the row "Label text", which opens the Label text page. The desktop layer panel has a "Label text" field.

On iPad, the label text of a layer and of a label class is a template in a field of text and chips. Typed text stays text, and a field is a chip. A word becomes a field only when it comes from the bar, a menu, or completion. A line break is a chip. A group holds text that shows only when its fields have a value. Backspace selects a chip, and a second Backspace deletes it. The segments Blocks and Code show the one stored text as chips or as expression text. Blocks write the text only when you edit in Blocks, so text that you do not edit stays as it is. Other expression text shows as a chip with the expression, and text that does not parse shows as a red chip. While the field has the focus, a bar sits on the top edge of the keyboard that the system reports. With a hardware keyboard, the bar sits on the shortcut bar of the system, or at the bottom of the screen. The bar has the tabs Fields and Functions, Group, Line break, and a chip for each field with its value in the feature of the preview. With no selection, the group takes the field next to the caret. It also takes the text before the field back to the start of the line, and the text after the field to the end of the line, if that text does not touch another field. The Functions tab puts the selected field in the first slot of a function. Below the field, a preview shows the label for the selected feature, or else for the first feature. The preview draws the label on the color of map paper, with the font, the style, the color, the halo, the case, and the letter spacing of the labels. Its text size is from 17 pt to 32 pt, so that a small label is easy to read. A caption below the preview names the feature. A tap on a field chip opens its popover. The popover opens below the chip if it fits above the bar, or else above the chip. It stays between the top safe area and the bar, and its rows scroll if it does not fit. The popover of Area, Perimeter, or Length starts with the row Unit. A number field has Decimal places, which writes `round`, and Thousands separator, which writes `format_number`. A text field has Case, which writes `upper`, `lower`, or `title`, and Trim spaces, which writes `trim`. When empty writes `coalesce` with a text or another field. In a group, the choice Hide group hides the group when the field is empty. "Wrap in function…" puts the field in the first slot of a function, and "Remove field" deletes the chip. The badge of a chip shows its format.

On iPad, a value, such as the Expression field of the Classify form, is a field of tokens with the segments Blocks and Code. A field, a number, a text, and an operator are chips. A function is a block with a slot for each argument. An empty slot shows the name of its argument and takes the caret, and a filled slot after the first shows the name before it. Digits make a number, `'` starts a text, and an operator char makes an operator chip. A word stays text until a space, an operator, or Return. Return picks the first field or function whose name starts with the word, and a function name with `(` makes the block of the function. Tab goes to the next slot, and `,` goes to the next slot of the block. Below the field, a preview shows the value for the selected feature, or else for the first feature. A tap on the field opens a tray with the tabs Fields, Functions, and Operators, a search field, and the rows of the tab. The functions are in groups by category, and each has a short hint. In the label text and in a value, a chip moves by drag. On iPad, a long press on a chip lifts it. The chip follows the finger with a shadow, and its old place is dim. A style can have a mask (a region of the world that limits the style). The region is a value range of a raster layer, or the polygons of a polygon layer. The lower limit of the range is in the range, and the upper limit is not. The land of a height layer is the range from 0 up. A raster mask also has an offset in points. A positive offset grows the region, and a negative offset shrinks it. An offset of minus half the weight of the band line at the edge of the range keeps the fill off that line. The fill and the stroke of a polygon layer, and the stroke of a line layer, draw only inside the mask. The stroke of a polygon is its own outline cut by the mask, so the edge of the mask gets no stroke. You draw a polity past the coast into the sea, and with a land mask its fill and its border stop at the coast.

A polygon mask cuts the geometry of each feature in longitude and latitude, and each view uses the cut geometry. A raster mask follows the raster as each view draws it, at the scale and the smoothing of that view. Its region is the pixels where the shown height of its layer is in the range, without the lakes that the layer draws. A GPU pass then grows or shrinks the region by the offset, at the pixels per point of the view, and it does not shrink the region at the edge of the world. The layer of the mask does not have to be visible. On the globe and in the flat view, a GPU pass cuts the pixels of the masked layer. In a map frame, the app traces the outline of the range on the pixels of the whole frame only. On the screen, the pixels per page point are the power of 2 at or above that of the screen, with at most 4096 pixels on a side. A pan of the page or a zoom out keeps the outline. In an export, the resolution is that of the raster image of the PDF. The outline clips the fill and the stroke as a vector path, so the PDF has vector paths that follow the coast of its raster image. The labeler gets the part of each polygon inside the outline, so a label stays inside the mask.

The Mask row below the rules of the Style section opens the Mask page. The page has "None", a row for each raster layer, and a row for each other polygon layer. A raster mask has a minimum, a maximum, and an offset, and a blank limit means no limit. A change of the layer of a raster mask keeps the offset. A tap on a height layer sets its land. The mask is part of the style, so each map has its own mask, and the panel of a layer in a frame also has the Mask row. In the desktop layout, the Mask menu, the range fields, and the offset field are below the rules. If the layer of a mask goes, the mask goes.

The symbolizers must give enough artistic range that the output does not look like a survey map.

| Symbolizer | Options in version 1 |
| --- | --- |
| Stroke | Solid, dashed, textured brush, taper along the line for rivers |
| Fill | Solid color, pattern, texture image, hatch lines |
| Edge effect | Coast lines repeated outward into water, inner shade along a border |
| Marker | Circle, square, diamond, triangle, or star, with a solid or hatched fill |
| Point symbol | SVG symbol with size and rotation from attributes |
| Scatter | Symbols spread inside a polygon, for forests and mountain ranges |
| Raster | Color ramp, smooth or stepped, opacity, blend mode, band lines, smoothing, hillshade |
| Image | Opacity, blend mode |

Textures and blend modes become raster images in PDF and SVG output. All other symbolizers stay vector.

A symbol is an SVG file that the user adds. The project file holds the SVG files, and a new project has no symbols. If a style names a symbol that the project does not have, the app draws a small dot. The size of a symbol is its longer side in points. The rotation is in degrees, clockwise from the top of the page. A symbol keeps the colors of its SVG file, and a tint replaces them. A label does not overlap a point symbol. Labels can overlap scatter symbols at a cost, so a city in a forest still gets its label.

The spacing of a scatter is the minimum distance between two symbol centers, in points. The scatter puts its symbols on a fixed grid on the ground. The grid has levels, and each level has cells of half the size of the cells of the level above it. Each cell has one candidate point at a random position, and the feature ID and the cell give the random value. A candidate becomes a symbol if no symbol of a coarser level is near it. The scale of the map selects the level. A pan does not move a symbol, and a zoom adds symbols or removes symbols but does not move one. The same polygon gives the same symbols after a reload, on the globe, on each map, and in each export.

## Labeling engine

The labeler is a standalone library that takes page-space geometry, label classes, and obstacles, and returns placed glyph runs. It is the main differentiator, so its work starts first and it has its own tests.

The engine supports the placements that readers notice on a good map.

| Feature type | Placements |
| --- | --- |
| Point | Positions around the symbol in a preference order, with an optional leader line |
| Line | Text that curves along a smoothed copy of the line, above, below, or centered, with repeats on long lines |
| Polygon | Text that curves along the long axis of the shape and spreads its letters, or a horizontal label at the visual center |
| Graticule | Polygon text along the parallel with the most room, with spread letters, and point and horizontal polygon text that follows the parallels |
| Polygon too small for its label | Label outside the shape with a leader line, or a smaller font step |
| Graticule and frame edge | Text at the frame edge, aligned to the line |

Placement runs in five steps.

1. Generate candidates. Each feature gets a list of possible positions from its label class.
2. Score. Each candidate gets a cost from position preference, curvature, distance from the feature, and overlap with obstacles.
3. Place by priority. The engine places the best candidate of each feature in priority order and skips candidates that collide.
4. Improve. A local search moves and swaps labels to lower the total cost. The search uses a fixed seed, so the same input always gives the same output.
5. Fall back. For each label that does not fit, the engine tries the fallbacks of its class in order: smaller font, stacked lines, abbreviation, leader line, and then removal.

The engine returns each unplaced label with a reason. The app lists them, so no label goes missing in silence.

Manual control is part of the design and not a repair tool. You can pin a label, move it, select a different candidate, or exclude it. A pinned label becomes a fixed obstacle, and the engine places all other labels around it.

The library takes its fonts through Parley and measures real glyph outlines. Collision tests use one box per glyph on curved text, so curved labels pack tightly. A line label tries positions along the whole line, and its letters follow a parallel copy of the line, so the letter spacing stays the same in a bend. Above the curve limit, the turn between two letters adds a cost, and the hard limit is 1.6 times the curve limit. A position where two letters overlap, or where a gap between letters grows or shrinks too much, is not used.

A polygon label uses only the part of the polygon inside the frame, and the largest part if the shape has more than one. The visual center is the point farthest from the edge. The long axis is the path between the two points that are farthest apart inside the shape, and it stays near the middle of the shape. If the axis is at least 2.5 times the width of the shape, the label curves along the axis. Otherwise, the label is horizontal at the visual center. A class can also make all its labels curved or all its labels horizontal. The letters of a label spread to fill a part of the axis or of the width of the shape, up to the spread limit of the class.

A polygon label class has more options. It ranks nine zones inside the polygon and eight zones outside it, and it can block a zone. The zones inside are the cells of a three by three grid over the shape, and they apply to horizontal text. A label in a zone outside the polygon gets a leader line. The leader line starts at the centroid, at the visual center, or at the nearest point of the outline. The class sets the look of the line: whether it shows, its color, width, and dashes, a halo, a dot or an arrow at the anchor, and a gap at each end.

A label avoids the holes of the polygon, and a class option lets it cover them, for example over the islands of a lake. Another option makes a label avoid the other polygons, as it avoids holes. A class labels only the largest part of a polygon, or each part where the label fits. A large polygon can repeat its label at a distance that the class sets. A label can go past the outline by a distance that the class sets. A part of the visible polygon with less area than the class minimum gets no label.

The caller gives the graticule as lines of latitude in page space, each from west to east. Text that follows the graticule uses a copy of the nearest parallel through its position. The text is straight where the parallels are straight, and it curves on a conic map. A polygon label along a parallel tries the curves through several points deep inside the shape, and the curve with the longest part inside the shape costs least. Its letters spread as on the long axis. The text reverses where it would be upside down on the page. A class can turn this off, for example for text near a pole.

The labels use the fonts of the system. The app also ships Noto Sans, which is the default font. A label style names a font family, and the project file holds only that name. The font picker has a search field. On iPad, it is the font picker of the system. A project looks the same on two devices if both devices have its fonts. If the device has no font of that family, the labels use Noto Sans, and the panel of the layer shows a warning that names both fonts. PDF export embeds a subset of each font.

The test set is real-world data, for example Natural Earth, rendered to images and compared with approved reference images. Real data has harder label problems than most fantasy maps.

Clean-room has a strict meaning here. The design comes from published research and from the public description of Maplex behavior in Esri documentation. No one on the project reads Esri code or decompiles Esri software. The starting points are Imhof's rules for name placement (1975) and the label placement study by Christensen, Marks, and Shieber (1995).

## Maps and the atlas

The atlas has three levels: maps, pages, and map frames.

A map shows the layers of the world in one projection. It has a name, a projection, a switch for each layer, a style for each layer, and label classes. A map has no extent, no scale, and no page size. A map frame shows one map. A new map frame and its map are made together, and a delete of the frame deletes its map. The Frame tab of a map frame has the name of its map, and you rename the map there. Each map has one projection center. For another center, you add another map frame.

A map style is a named set of layer switches, full layer styles, and label classes that many maps share. It gives a series of maps one look when each map has its own projection. A map links to one map style or to none. A map that links to a map style draws each layer with the style in the map style. A change in a frame of the map is a local change of the map. A local change is a style, a switch, or label classes that the map holds for a layer. It replaces the style, the switch, or the classes of the map style for that layer only. "Update map style" moves all local changes of the map into its map style, so that each map that links to it gets them. "Reset to map style" removes all local changes of the map. Each of them is one undo step. When a map links to a map style, the map drops its own styles, switches, and label classes. One undo step brings them back.

The app has two workspaces, World and Atlas. In the World workspace you draw and edit the features. In both workspaces, you select features and edit their attributes in the inspector and in the attribute table. The Atlas workspace holds the maps, the pages, and the map frames. You edit a map in a frame, at the scale of the page, so that the labels and the styles show as they export. The labels of a frame come from the whole frame, so a pan or a zoom of the page does not change them.

A page is one page of the atlas. It has a page size, its map frames, and its furniture (the items around the maps). The page size has presets and a free value, with units. A page has a paper color. Version 1 has text boxes, legends, scale bars, north arrows, and color keys. A page can have any number of each.

A map frame is an area on a page that shows one map. Its shape is a rectangle or a polygon. A polygon can have notches and holes, for example a cut-out for an inset. The frame holds its shape on the page, and the center, the scale, and the rotation of the map in the shape. The map draws only inside the shape, and the neatline follows the shape. The extent of the frame comes from the shape and the view. A frame also holds its fill, its neatline, its border, and its graticule. The fill is a color behind the map, and with the fill off, the paper shows through. One map can be in no frame, or in many frames on one or many pages. Thus an inset or an island chain is many frames on one page. A locator map is a map in a small frame, for example in the orthographic projection with a fill for the region of the main map.

Each text box, scale bar, north arrow, legend, and color key links to one frame of its page. A new item links to the largest frame. When a frame is deleted, its items link to the largest frame that stays.

A scale bar has one of six styles: alternating, double alternating, hollow, single division, stepped line, or line. It shows one or two units. The second unit is on the other side of the line and has the same zero. The bar sets its divisions, equal or doubling, the subdivisions of the first division, a division before zero, the division value, the fills, the marks, the numbers, and the unit label. The fill of a division is solid, hatch, cross-hatch, or none. The division value can follow the width of the box. The text of a text box is a template, with the same field of text and chips as the label text of a layer. A chip is a value of the page or of the frame of the text box: the scale, the map name, the page name, the page number, the page count, or the date. For example, the text "Scale " and a scale chip show "Scale 1:25,000,000". The scale is a fraction or a relative scale, for example "1 cm = 250 km". The page unit of a relative scale is centimeters or inches, and the ground distance uses the display units of the world. The numbers of a scale have three significant digits. The date is long, for example "November 8, 2026", or ISO, for example "2026-11-08". The bar above the keyboard has the page values in place of the fields, and the popover of a chip sets its format. The panel shows the frame of the text box only while the text uses the scale or the map name. If the text box has no frame, a chip of the frame adds the link to the largest frame. A value of the frame with no frame shows a dashed box on the screen and nothing in an export. Each text part of an item of furniture, for example the title of a legend or the numbers of a scale bar, has the text settings of a label class.

A color key shows the color bands of one raster layer. It links to a raster layer that its frame shows. A new key shows the height layer of the frame, or else the top raster layer. If the frame does not show the layer, the key draws nothing. A key has one of two layouts. In the layout "Strip", the boxes have equal width and touch, in a row. A value shows at each line between two boxes and at each closed end, and the unit shows at the open end. On a height layer, the strip can split at sea level: the sea row is above, with the deepest band at the left and the depths as positive values, and the land row is below. The display Gradient shades each box, and the display Grey shows one bar with its two end values. A strip can show a second unit below each row, with a name, a factor, and an offset. Its values have the decimals of the values of the first unit. The box width and the box height are in millimeters, and an empty value follows the text and the width of the key. If a row of a strip does not fit in the key, the boxes get smaller, and a box with a set width and height keeps its shape. If the values do not fit between the lines, it shows every second or third value, counted from a closed end. In the layout "List", each band has a box in a column, from the top band down, with a text to the right. The text is the name of the band, or else its range, for example "Under 250", "250–500", or "Over 2,000". The key can show the name of each band inside its box, for codes such as "3-A", and then the text to the right is the changed name or the range. The title, the values, the values of the second unit, and the names in the boxes each have their own text settings. The lines around the boxes have a color and a width, and a width of 0 draws no lines.

The screen shows what the export holds. A frame on the screen has the line widths, the sizes of the symbols, and the sizes of the text of the printed page at the zoom of the view, so a 1 pt line is 1 pt on paper and grows and shrinks with the page. A raster layer shows at the resolution of the page. The Atlas workspace shows one page, and each panel opens from the selection or from the Panels menu. On the iPad, each panel is a pane of the dock. A tap on a frame or on an item of furniture opens the Properties panel. A tap on the page outside the frames opens the Pages panel, with the page size, the paper color, the template, and the layout grid. On the iPad, the page card goes to the previous page and the next page, and a tap on its text opens the Pages panel. In the overview of all pages, you open, reorder, add, and delete pages. On the iPad, the tools of the tool column add the map frames and the furniture. On the desktop, the Add menu in the tool bar adds a map frame, a map from a region, text, a legend, a scale bar, a north arrow, or a color key to the page. On the iPad, the actions in the top row are Undo, Redo, the Panels button, and the Dock button. The Attributes panel is a pane beside the panes of the frame. On the desktop, "Maps" in the tool bar shows and hides the panel of the selected frame, and with no frame selected it is a menu of the frames.

In the Atlas workspace, you move and resize a frame on the page, you edit the vertices of its shape, and you pan, zoom, and rotate the map in it. A frame has four panels: Frame, Projection, Layers, and Labels. On the iPad, the Frame panel is part of Properties. Properties shows the settings of the selected map frame or item of the page, and with no selection it shows a hint. A selected frame or item opens Properties, and the tiles open the others. A frame panel opens in the pane of the panels of its group, or in a new pane. At first each frame panel is a group of its own, and tabs that you merge make a group. The panels show the selected frame. With no frame selected, a frame panel shows a hint, for example "Select a map frame to see its labels." On the desktop, the four panels are the tabs of the panel of the frame. The Frame tab holds the map of the frame, its map style, its shape, center, scale, rotation, neatline, border, and graticule. The Map style row shows the name of the map style of the map, or None, and "Edited" follows the name when the map has local changes. Below the row, "Update map style" and "Reset to map style" show when the map has local changes. The row opens the Map style page. The page lists None and each map style, with a check on the map style of the map. A tap on a row links the map to that map style. A swipe to the left on a map style shows its Rename button and its Delete button, as in the layer list. An empty name, or the name of another map style, keeps the old name. The page also has "Save as map style…". "Save as map style…" moves the switches, the styles, and the label classes of the map into a new map style and links the map to it. The frames of the map look the same after it. The row of the new map style is then a name field, with the name selected, so you type its name. With None, and with a delete of a map style, each map that linked to it gets a copy of the switches, the styles, and the label classes that it drew, so its frames look the same. The neatline has a switch, a color, and a width. It is a line on the edge of the shape, and it follows each notch and each hole. It belongs to the frame, so two frames of one map can have different neatlines. It is a vector line in a PDF. The border is a band around the frame, at a set distance outside the bounding box of the shape. It has a switch, a width in millimeters, a style, colors, and a stroke. It also has a distance in millimeters for each side. "Border distance" sets all four sides, and the switch "Distance by side" shows the distance of the top, the right, the bottom, and the left. A negative distance puts that side of the band inside the bounding box. A part of the shape that crosses the band covers it there. The band, its stroke, and its grid labels stop at the gap, which is a set distance around the shape. Thus a polygon frame can reach past the band at one place, as a peninsula reaches past the page margin of a printed atlas. The space between the shape and the band is not filled, so another frame can show there or cross the band. A solid band has one color. A graduated band has two colors, and the color changes at each place where a meridian or a parallel meets the middle of the band. The lines are at the graticule interval of the frame, also while the graticule is off. The stroke is a line on the inner and the outer edge of the band, with a switch, a color, and a width. On a graduated band, the stroke also goes across the band at each change of color. The reference grid follows the graticule. Each interval of the meridians along the top and the bottom of the band is a column, and each interval of the parallels along the left and the right of the band is a row. The choice "Columns" gives the columns the letters A, B, C and the rows the numbers 1, 2, 3, or the reverse. The columns count from the westmost cell of the shape, and the rows count from the northmost cell. Thus on a conic map, the top and the bottom of the band can show different columns. A label sits at the middle of the band, at the middle of the part of its interval that is beside the bounding box. An interval that is too short for its label, that is off the sphere, or that is under the shape has no label. The grid has its own switch below the border, and the row "Grid labels", which opens the Text section of the labels. The labels sit in the band, so the grid turns the border on, and the border turns the grid off. The border can be on without the grid. The band and the labels are vector items in a PDF. While the graticule is on, the tab shows its interval, its color, its width, and the row "Edge labels". The row opens the Edge labels page. The page has the label format, "DMS" or "Decimal", and the segments "Meridians" and "Parallels". Each segment has the switch "Show labels", the Text section, the Placement section, and the switches of the four edges. The Interval stepper shows the interval that the frame draws. The buttons of the stepper set the interval by hand, and the switch "Auto interval" makes the interval follow the scale again. The Projection tab edits the projection of the map and shows the distortion in the frame. In the Layers tab, the eye of a row is the switch of that layer in the map. The arrow of a row opens the panel of the layer. In a map that links to a map style, "Edited" marks each layer with a local change. The panel has the full Style section of the World workspace, and it edits the style of the layer in the map. The globe style stays. "Add rule", "Move rule up", "Move rule down", and "Delete rule" work there. "Reset to map style" in the panel removes the local changes of the layer. It shows only when the layer has local changes. "Copy globe style" replaces the style of the layer in the map with a copy of the globe style. The panel of a raster layer has the opacity and the Style section of the World workspace: the display, the blend mode, the smoothing, the color stops with their pages and cards, the band lines, and the hillshade. The panel of an image layer has its opacity and its blend mode. Each map has its own value of each of them. The rivers belong to the globe, and a map frame draws no rivers. The eye in the World workspace has its own state and does not change a map switch. A new layer is on in each map. The Labels tab edits the label classes of the map. The tab lists the classes of the vector layers in priority order. The top class places its labels first. You drag a row by its handle to change the order, and the page of a class also has "Move up" and "Move down". "Add class" adds a class. The page of a class has three segments: Text, Placement, and Conflicts. The Text segment holds the name, the layer, the label text, the filter, the font, the style, the size, the case, the letter spacing, the color, and the halo. The style row lists the faces of the font family, for example Regular, Italic, and Bold. The case is normal, uppercase, lowercase, title case, small caps, or all small caps. Small caps use the small caps of the font. If the font has none, the labeler makes them from capitals at 70 % of the size. The letter spacing is a percentage of the size. The halo is a stroke around the text, with a switch, a color, and a width. The filter has the same editor as the filter of a style rule. The placement choices come from the feature type of the layer. A point label goes around the point, or to one side of it. A line label goes above or below the line, above it, below it, or on it. A polygon label has the placement "Best fit", "Curved", "Along parallel", or "Horizontal". "Best fit" curves the label along the long axis of a long shape, and it puts the label horizontal at the visual center of a compact shape. "Curved" curves the label along the long axis of each shape. "Along parallel" puts the label along the parallel with the most room in the shape. The Placement segment holds the placement and the offset, which is the distance from the feature. A point class also has the Positions page. It lists the eight positions around the point in rank order, and the labeler tries them in that order. You drag a row by its handle to change the rank, and the switch of a row blocks or allows the position. A line class also has a repeat switch and a repeat interval, a curve limit in degrees per letter, and a smoothing of the line. A polygon class has no offset. It has a spread, which is the most extra space between two letters, as a multiple of the size. A polygon class that can curve also has a curve limit. A point class and a polygon class with "Best fit" or "Horizontal" have the switch "Follow parallels", which makes the straight text follow the parallels. Text that follows the parallels stays upright, and the switch "Allow upside-down text" lets it read from west to east everywhere. The Conflicts segment holds the buffer, which is a margin around the label that other labels keep free. It also holds "Remove duplicates" with its distance, the smallest distance between two labels with the same text. "Remove duplicates" is off in a new class, and it is for a feature whose name repeats because the data is in pieces. "Move up", "Move down", and "Delete class" are at the bottom of each segment. A map can have more than one class for a layer, and each class whose filter matches a feature labels that feature. A layer with no class of its own in the map uses the label settings of the layer, and a layer with its classes deleted has no labels in the map. A change in these three tabs changes the map, so it shows in each frame of the map. You pin, move, and hide a single label in a frame, because each manual change belongs to one frame.

If the box of a frame is narrower than 88 points on the screen, the handles at the middle of its top edge and its bottom edge do not show. If it is shorter than 88 points, the handles at the middle of its left edge and its right edge do not show. If it is smaller than 44 points, its handles are on a box of 44 points around its middle, and a drag of a handle moves the corner by the same distance. The row "Add hole" of the Frame tab adds a hole to the polygon. On iPad, the controls of the Frame tool have Snap and Grid. The panels have no delete row. While a frame or an item is selected, the Move tool has Deselect alone. On the desktop, while the Frame tool, the Select tool, or the Move tool has a selection, the tool bar has Deselect. On iPad, the controls of the Select tool have Snap and Grid. While a frame or an item is selected, they also have "Delete selection". While something is selected, they also have Deselect. Esc does the same on the desktop.

A page template holds the page size, the margins, and the positions of the furniture. Many pages share one template, so the atlas has one look. The atlas is the ordered list of the pages.

The atlas exports to three formats.

| Format | Use | Notes |
| --- | --- | --- |
| PDF | Print and books | One file with all pages, or one file for one page. Text stays selectable, and fonts are subset and embedded. |
| SVG | More work in Illustrator or Inkscape | One file per page, with layers kept as groups. |
| PNG or TIFF | Web and virtual tabletop tools | One file per page at a set resolution, rendered in tiles. |

Export uses RGB color in version 1. CMYK output for commercial print is an open question.

A place-name index with grid references comes after version 1. The data model already supports it, because labels come from stored features.

## Editing scope

Version 1 draws the shape of the world in the app and leaves color artwork to external tools.

The app has seven editing tools in version 1.

- Heightmap painting on the globe.
- The toolbox, with polygonize and five other tools.
- Freehand lines and polygons on the globe.
- Point placement, with the attributes in the inspector, for cities, landmarks, and other named places.
- An attribute table with sort, filter, and bulk edit.
- Line and polygon editing by vertex and by reshape with a stroke, with snapping and a smooth operation. A stroke also adds an area to a polygon or subtracts an area from polygons, and a stroke splits lines and polygons. Subtract cuts the key polygon of the selection out of the other selected polygons. Merge joins the selected features of a layer into one feature.
- Label editing on the map: pin, move, select a candidate, exclude.

Photoshop, Illustrator, and similar tools keep color artwork and textures. The command Replace from file makes that round trip cheap.

A full vector drawing tool set comes after version 1.

## Phases

The labeling prototype came first, and it is done. The work after it has eleven phases, in the order of the table. The globe comes first, because you draw the world in the app. Thus the drawing tools arrive before the map tools.

| Phase | Name | At the end of the phase |
| --- | --- | --- |
| 0 | iPad test loop and CI | Each PR arrives on the iPad through TestFlight, and CI builds all four platforms. |
| 1 | Globe and heightmap painting | You paint a heightmap on the globe with Apple Pencil or a pen tablet, in the real app. |
| 2 | Projects and storage | The world that you paint is a project file that you can close, open again, and move between devices. |
| 3 | Toolbox and freehand lines | The toolbox turns the heightmap into topography polygons, and you draw rivers and borders as lines. |
| 4 | Maps, frames, and projections | You make a map in a projection that fits its region, and you place it in frames on a page. |
| 5 | Vector data editing | You place cities and other points, edit attributes, and edit lines and polygons by vertex. |
| 6 | Styling | Rule-based styles draw all symbolizers of version 1 on screen and in PDF. |
| 7 | Labeling in the app | Labels come from attributes, polygon labels and fallbacks work, and manual changes stay. |
| 8 | Atlas and export | An atlas of pages exports as a multi-page PDF, SVG files, and raster files. |
| 9 | Import | Files from other tools come in as layers, and a replaced file keeps its extents, styles, and overrides. |
| 10 | Derived values | Styles, labels, and fields use the measures of features, the values of raster layers, and the flow of rivers. |
| 11 | iPhone | The app installs on iPhone, a finger paints the globe, and each screen has an iPhone layout. |
| 12 | Version 1 release | Version 1 is in the App Store and on the three desktop platforms. |

From phase 1 on, a phase is done only when it works on desktop and on iPad.

No phase is a command-line tool alone. Five command-line tools stay, and each one runs the same core crates as the app.

- `vale-labeler-demo` is the regression test of the labeler.
- In phase 2, the flag `--export-heightmap` of `vale-app` exports the first height layer of a project file as an equirectangular GeoTIFF.
- In phase 3, a command runs a toolbox tool on a project file.
- In phase 4, a command renders one page of a custom-radius world to PDF, with its frames clipped and a graticule.
- In phase 8, a command exports the atlas as a multi-page PDF.

The app prototype covers a thin part of phases 2, 4, 6, 8, and 9. It does not finish any of them.

### Labeling prototype

The labeling prototype differs from the design above in four ways. Each difference ends when the crate named for it exists.

1. A separate crate, `vale-labeler-demo`, holds the command-line tool for data loading, projection, and rendering. It is not published. It ends when `vale-render` and the later command-line tools take over its jobs.
2. The demo rasterizes with `vello_cpu` through the display list of `vale-render`. The design rasterizes the export with GPU Vello.
3. The demo has two hand-written spherical projections, Equal Earth and Lambert azimuthal equal-area. They stay in the demo as a fixed test input. The app uses PROJ through `vale-sphere`.
4. Of the five fallbacks in the labeling engine, the prototype has only the last one, removal with a reason. The other four arrive in phase 7.

The labeling prototype is done. The command `cargo run --release -p vale-labeler-demo -- --preset world` writes the labeled PNG.

### App prototype

The app prototype is a vertical slice. It makes a runnable app early. It takes a thin part of phases 2, 4, 6, 8, and 9 at once. It differs from the design above in nine ways. The command `cargo run --release -p vale-app` opens the window. A brush tool paints the heightmap, and a brush panel has the fifteen modes, the radius in kilometers, the size lock, the hardness, the flow, the strength, the flatten level, the angle of the Weather mode, the erosion of the Uplift mode and the Range mode, the wind and the rain shadow of the Erode mode, the Uplift mode, and the Range mode, the scale and the seed of the Warp mode and the Noise mode, the raise, the lower, the grain, the ridged variant, the invert switch, and the relief of the Noise mode, the spacing and the seed of the Range mode, the channel width of the Carve mode and the Erode mode, the floodplain of the Carve mode, and the floor and the ceiling. The size lock holds the radius as an angle on the sphere. The GPU holds the heightmap in tiles of 256 pixels, as the CPU does. A lookup table has one entry for each tile of each face, and it takes 25 KB at faces of 8,192 pixels. A tile at the base level has no entry and takes no memory, so an empty world takes memory for the table only. A tile with memory is in a pool. The pool grows in textures of 64 tiles or more, and each new texture is as large as all textures before it. The first one takes 8 MB. Thus the pool takes at most two times the memory of its tiles, plus 8 MB. With memory in each tile, the pool takes 805 MB. A pool can also hold two levels of a map, and each level has its own part of the table. A detail map is such a pool, and it holds only the tiles under the map frames and the view. A worker thread reads the file and makes the six faces, and the status bar shows the progress. The import is one undo step. If the tiles that the import replaces are larger than the undo limit, the import has no undo step. The picture is not an undo step. The date in the list is the UTC date of the last change of the file. In the iPad layout, the start screen is a grid of cards with the theme of that layout. A card of that layout shows a blurred copy of the frame below a dark fill. egui draws the frame into a texture of the size of the screen, and then it copies that texture to the screen. Before its shapes, a card puts a marker with its egui order into the paint jobs. The patched copy of `egui-wgpu` ends the render pass at a marker with a higher order than the last capture of the frame. Then a hook of Vale shrinks the frame that is drawn so far into a texture at a quarter of the size. Each pixel of that texture is the mean of 4 by 4 pixels of the frame. Two shader passes blur the texture with a standard deviation of 20 points, and a new render pass continues the frame. Each card draws its part of the blurred texture through a paint callback, at 70 percent of the brightness, so that grey text has a contrast of 4.5 to 1 over a white canvas. The blur shows all the content below a card: the raster layers, the vector layers, the symbols, the labels, the graticule, and the map frames of the Atlas workspace. A frame has one capture for each order that has a card, and a frame with no card has no capture. The debug controls in the Toolbox panel show the frame time, and a checkbox there turns the blur off.

The brush stamps in a wgpu shader of `vale-terrain`, one pass for each face that the stamp touches. Up to 32 raise, lower, flatten, carve, ridge, deposit, or noise stamps share one pass. A smooth stamp has its own pass, because it reads the texels around it. A weather stamp, a warp stamp, and a push stamp have their own passes for the same reason. Each read of a level goes through the lookup table, and so does a read past a tile edge or a face edge. The globe shader reads through the same table. A pass cannot read the texture that it writes. Thus the pass draws the rectangle under the brush into a render target of about that size, and a copy moves the texels into the tiles. The render target takes about 20 MB for one stamp of the largest brush, and 134 MB at most. A warp stamp or a push stamp reads the texels of each face that it touches, so it draws each of its faces before the first copy. It uses one render target for each face, and at most three. While you paint, the pool is the working copy. At the end of a stroke the app reads the changed texels back into the heightmap of `vale-terrain`, which stays the document. The CPU stamp is the reference, and the tests of `vale-terrain` compare the two. The result of one stamp differs by at most 1 of the 65,536 levels, and by at most 2 in the smooth mode and in the weather mode. Over a stroke of many raise or lower stamps, the tests allow a difference of 3. Over a stroke of warp stamps or push stamps, the tests allow a difference of 2. A debug panel shows the stroke delay, which is the time from the frame that read the pen to the end of the GPU work.

The globe draws the visible vector layers over the heightmap, in draw order, with the fill, the stroke, and the marker of the layer style. Inside a layer, the globe draws in the order of a map frame: rule by rule and symbolizer by symbolizer, and all features of one symbolizer together. Thus the fills of a layer are below its strokes. An edge between two positions is the short arc of a great circle. The app adds points to an arc until the drawn line is at most a quarter of a pixel from the arc. The edge of the globe cuts each line at the exact place where the arc goes to the far side. A polygon that crosses the edge of the globe gets a fill that follows the edge between the two crossings. The outer ring of a polygon goes around the smaller of its two sides. The order of the positions in a file has no effect. A map frame draws the same edges as straight lines in longitude and latitude.

The globe and the flat view draw the rivers that the heightmap implies, and the Rivers switch of each height layer hides its rivers and its lakes. The project keeps the switch of each layer. A layer with its rivers off has no channel map on the GPU. `vale-terrain` keeps a coarse copy of the heightmap with at most 512 cells along a face. It fills each pit to its rim, and each land cell drains to a steep lower neighbor. A fixed scatter of that choice lets the streams on an even slope join. A cell is a river if at least 0.0005 steradians of land drain through it. The line of a river is a curve through its cells, with no corner at a cell. Four passes of smoothing move each cell of a river toward the cells above and below it, so a river on a slanted slope has no 45-degree zigzags. A channel map with two times as many texels along a face holds two rivers for each texel, each with its distance and its size. The first is the nearest river, for the lines. The second is the river with the deepest valley at the texel. At faces of 8,192 pixels, the channel map takes 25.2 MB on the GPU. The channel map also holds one fill level for each cell of the coarse copy, for the Deposit mode. Those levels take 3.1 MB. After each stroke and each undo, a worker thread computes the channel map again, and painting does not wait for it. The rivers are a preview, and they are not features of a layer.

When you zoom in, a window of 512 by 512 fine cells covers the region in view. The cells line up with the texels of one cube face. At faces of 8,192 pixels, one cell is 1, 2, 4, or 8 texels wide. The window has its own flow and its own channel map of 4 MB, and a river of the coarse map that enters the window keeps its size. In the window, the rivers are closer together. A small pan keeps the window, and a large pan or a zoom makes a new one on the worker thread. A River width slider below the Rivers switch sets the width of the lines. It goes from 0.05 to 4 on a logarithmic scale, and it starts at 1. A line is at least 0.7 channel texels wide, times the slider value if that value is below 1. A River opacity slider below it sets the opacity of the rivers and the lakes, and it starts at 90 %. Both are session settings, and they are not in the project file.

The globe and the flat view also draw the water of each filled pit as a lake. A lake cell is a land cell of the coarse copy that the fill raises. A group of lake cells that touch is one lake, also across a face edge. A lake shows if its cells cover at least the area of the Smallest lake slider, so the small pits of noise and erosion stay dry. The slider is below the River opacity slider. It goes from 100 km² to 1,000,000 km² on a logarithmic scale, and it starts at 2,000 km². It is a session setting, and it is not in the project file. In the iPad layout, it is a row of the Layers panel.

Each cell of a lake holds the level of the rim of its pit, and each land cell beside a lake holds the same level. A texel shows water where its height is below the blend of the 4 cells around it. Thus the shore follows the heights of the texels, and it has no steps of the size of a cell. Each face also holds the cells of the faces next to it, so a lake across a face edge has no seam. The lakes have the color of the rivers. A river line stops at the shore, and it starts again at the outlet.

The worker thread computes the lakes with the channel map. The lake levels are in one more layer of the channel map, and at faces of 8,192 pixels that layer takes 4.2 MB on the GPU. The window of small rivers has no lakes of its own, but in a close view the shore still follows the texels. A map frame draws no lakes.

The fifth brush mode, Carve, cuts a channel along each river under the brush. The coarse copy or the window gives only the flow: the drainage area and the smooth line of each river. The channel is cut at the full resolution of the heightmap. The width of a channel grows with the square root of its drainage area, and it does not depend on the size of a cell or on the zoom. The Channel width setting is the width of a river that drains 1,000,000 km². It goes from 0.05 km to 10 km, and it starts at 0.6 km. Thus a river that drains 3,000,000 km² has a channel about 1 km wide. A channel is at least one texel wide, so the flow of the heightmap can follow it. The bed of a channel is below the filled level of the coarse copy along the river, and that level does not go up along the flow. Thus the bed goes down along the flow, and the flow after the cut follows the channels. In this mode, the Strength slider sets the depth of the bed, and a larger river gets a deeper bed. A river with a large drainage area and a low slope also gets a flat floodplain at its filled level, on both sides of the channel. The Floodplain setting is the full width of that plain. It goes from 0 km to 100 km, and it starts at 10 km. The plain grows from no width at 100,000 km² to the full width at 1,000,000 km², and it fades away as the slope goes from 0.0002 to 0.001. Carve changes no ground farther than one texel past the channel or the plain. Where two channels meet, the ground takes the deeper cut. The distance to a river is measured on the sphere, and each face holds the rivers of the faces next to it, so a channel across a face edge has no seam. Carve reads the window where the window covers the ground, and the coarse copy on the other ground. Carve does not lower land below sea level, and it does not change the sea floor. The two settings are session settings, and they are not in the project file. In the iPad layout, they are rows of the Brush panel. One Carve stamp on the GPU differs from the CPU stamp by at most 1 level. Carve is a test of a brush that erodes, and the design of version 1 does not include it.

The sixth brush mode, Erode, uses stream power. Stream power is a rule that lowers a cell in proportion to the slope to the cell below it and to the square root of the area that drains through it. While you hold the brush, a worker thread repeats a step, and each step computes the flow again from the lowered cells. The valleys then branch up toward the ridges. A stroke works on the cells of the view or on the cells of a window of the brush. The cells of the view are the cells of the window in a near view, and the cells of the coarse copy in a far view. The window of the brush has 512 by 512 cells around the pen, and its cell is the largest power of two of texels that keeps 16 cells in the radius of the brush. If that cell is smaller than a cell of the view, the stroke works on the window of the brush. Thus a small brush cuts narrow valleys in a wide view. The water of the ground of the view comes into the window of the brush from outside, so a river keeps its size there. That ground is the ground of the view at the start of the stroke, and the worker computes its flow one time. When the brush comes within 3 radii of the side of its window, the worker makes a new window around the pen. A cell of the old window keeps its height in the new window, and the water still comes in. A stroke on the cells of the view keeps the cells that it had at its start. In a window, the erosion fades to zero at the window side.

A step moves each cell to a weighted mean of its height and the new height of the cell that takes its water. Thus a cell does not go below that cell at any strength. The strength of the brush and the time since the last step set the weight. The floor of a filled pit stays until its rim comes down to it. Erode does not treat sea level as special. The flow of a step continues below the coast to the lowest ground, so a river mouth becomes an inlet, a coast under the brush moves back, and a slope of the sea floor gets canyons. A flat sea floor has no slope, so it stays. The rivers on the screen and the Carve mode use the flow of the land alone. On the cells of the coarse copy, a river cell lowers only its channel. The channel has the width of the Carve channel and no floodplain, and it gets the drop of the river cell. The other texels of a river cell get the mean drop of the cells around it that are not rivers. Thus the slopes between the rivers go down much less than the rivers. On the cells of a window, each texel takes a smooth blend of the drops of the nine cells around it, with the weights of a quadratic B-spline. Thus no cell edge shows, and a channel that crosses the cells on a diagonal has no row of dots. The blend makes a channel that is one cell wide shallower and wider. If a cell is one texel wide, the texel takes the drop of its cell. Painting does not wait for a step, and one undo step puts back the ground from before the stroke. One Erode step on the GPU differs from the CPU step by at most 1 level. Erode is a second test of a brush that erodes, and the design of version 1 does not include it.

The Erode mode and the Uplift mode use rain. The water of a cell in the flow is its area times its rain, and the rain is a value from 0 to 1. A wind brings the rain from one side. The world has a Wind setting, which is the compass direction that the wind comes from, and a Rain shadow setting from 0 to 100 percent. A new world has a wind from the west and a rain shadow of 0 percent. The brush panel of the Erode mode and of the Uplift mode shows the two settings. In the iPad layout, the wind is a compass dial. The two settings are in the project file, and a change of them is an edit of the world with an undo step. All strokes use the one wind of the world.

To find the rain of a place, the worker follows the wind back from the place for 48 steps of 2 cells each. Then the air moves forward along that line to the place. The air starts full of water. Over the sea, the air takes back a quarter of its missing water at each step. Where the ground rises along the wind, the air loses its water: a rise of 1,500 m leaves `1 / e` of the water. Where the ground goes down, the air keeps its water. The rain of the place is the water of the air times a part that grows with the elevation, from 0.15 at sea level to 1 at 3,000 m. A scale sets the largest rain on a windward slope to 1. Thus the windward side of a range gets more rain than the lee side, and higher ground on the windward side gets more rain than lower ground. The lee side is the rain shadow. A wet slope cuts deeper, denser valleys, and the lee side stays smoother.

At a rain shadow of `s`, the rain of a cell is `1 - s + s` times the rain of the wind. At 0 percent, each cell gets a rain of 1, and the result is the same as without the rain. The worker computes the rain at the corners of squares of 8 cells, and a cell takes a blend of the 4 corners around it. A corner on a face edge is one place on the sphere, so the rain is continuous across the edge. An Erode stroke computes the rain one time, from the ground of its first step, and again for a new window. The first step of a stroke takes about 1.4 times as long as before. An Uplift stroke computes the rain of the rectangle of each step, because the stroke raises the ground. The water that comes into a window from outside has no rain.

The seventh brush mode, Weather, limits the slope angle. A stamp compares each texel under the brush with its 4 neighbors on the face. Where the difference between two texels is more than the limit, ground moves from the higher texel to the lower one. One stamp moves an eighth of the part of the difference that is above the limit. The weight of a pair of texels is the smaller of their two brush weights. No ground moves across a face edge. Each pair moves a whole number of levels, so the sum of the levels stays. The limit is the tangent of the angle times the size of a texel. Each face uses one texel size, which is a quarter of the circumference of the world divided by the face size. A texel near the middle of a face edge is smaller, so the true angle there is steeper by a factor of up to 1.4 in the tangent. The Angle stepper of the brush panel goes from 0.02 to 20 degrees, and it starts at 0.5 degrees. At faces of 1,024 pixels on a world of the size of the Earth, a texel is 10 km wide, and painted land has slopes of 3 degrees or less. Weather is a test of a brush that erodes, and the design of version 1 does not include it.

The eighth brush mode, Uplift, raises the land and erodes it in the same stroke. Each stamp raises the ground as a Raise stamp does. In this mode, the Strength slider has the name Uplift, and it sets the rate of the uplift. The rise of a stamp grows with the Erosion setting, up to 2 times at 100 percent. Thus one stroke gives a range of about the height of a Raise stroke at each setting. More strokes on the same range do not add their heights, because the erosion grows with the relief. A worker thread keeps the cells of the erosion for the stroke. The size of a cell follows the brush: it is the largest power of two of texels that keeps 16 cells in the radius of the brush. Thus the valleys are narrow against the range in a view of a continent and in a near view. The cell is not larger than a cell of the coarse copy. The cells are a window of 512 by 512 cells around the pen. When the brush comes within 3 radii of the side of the window, the worker makes a new window around the pen. A cell of the old window keeps its height in the new window. For each set of new stamps, the worker raises its cells under those stamps, and then it runs 4 Erode steps there. Each step computes the flow again, so the valleys of one step collect the water of the next step, and the valleys branch. The flow is that of a rectangle of cells around the stamps of the set. The water leaves at the sides of the rectangle, and no river comes in. Thus the time of a step follows the size of the brush, and not the size of the window or the amount of land. The rate of the 4 steps together is 12 times the Erosion setting times the number of stamps in the set, for a brush radius of 16 cells. The rate grows with the square root of the number of cells in the radius, because a slope with no valley erodes less on smaller cells. Thus the erosion follows the amount of the uplift, and not the speed of the pen or of the worker. After the steps, the app adds one Weather stamp for each 4 stamps of the set. The weight of that stamp is the Erosion setting, and its limit is the angle of the Angle stepper. The Erosion slider goes from 0 to 100 percent, and it starts at 50 percent. At 0 percent, the stroke makes no steps and no Weather stamps, so the result is that of the Raise mode. A cell is one texel or more, so a brush with a radius of a few texels gives a smooth hill. A pen that holds still adds no stamps, so it changes nothing. The cells of the worker do not get the changes of the Weather stamps. Painting does not wait for a step, and one undo step puts back the ground from before the stroke.

Uplift is not procedural world generation. The mode has no noise and no random numbers. It changes the ground under the brush only, and the stroke sets the line, the width, and the height of the range. The valleys come from the flow of water over the land that you painted. If each step is ready in the frame of its request, two equal strokes on equal ground give equal results. A slower worker makes other sets of stamps, so the results differ in small ways. Uplift is a test of a brush that builds relief, and the design of version 1 does not include it.

The ninth brush mode, Warp, moves the ground sideways and adds no height. Round stamps leave a coast in smooth arcs and a ridge in a straight line. A Warp stroke gives the coast bays and headlands, and it bends the line of the ridge. Each texel under the brush takes the height of the ground at an offset place. A noise function of the 3D point of the texel on the sphere gives the direction and the size of the offset. The noise is value noise: each point of a 3D lattice has a fixed vector, and the noise changes smoothly between the lattice points. The noise has one size of features. The world has a seed, which is a number in the project file that selects the noise field. A new world has the seed 0. In this mode, a Seed stepper of the brush panel sets the seed of the world, from 0 to 999. A change of the seed is an edit of the world, so it has an undo step in the project file. The place and the seed fix the field, so each stamp of a stroke moves the ground along the same field. Each stamp reads the ground that the stamp before it left. Two equal strokes on equal ground with the same seed give equal results.

In this mode, the Strength slider sets the largest offset of one pass, in kilometers. It goes from 1 to 500 km, and it starts at 50 km. The mean offset is about half of that distance. The weight of the brush and the flow scale the offset. A Scale slider sets the size of the features of the noise. It goes from 5 to 2,000 km, and it starts at 200 km. The scale is not smaller than 2 texels. The offset is not larger than the distance to the brush edge minus 3 texels, so it goes to zero at the edge. Thus each texel that a stamp reads is under the brush, and each new height is between the lowest height and the highest height there. Flat ground stays flat. A brush with a radius of less than 3 texels changes nothing. The height at the offset place is a blend of the 4 texels around it. The place is a point on the sphere, and a read past a face edge blends the texels of the next face. Thus a stroke across a face edge has no seam. The blend softens sharp detail under a long stroke. An offset far below one texel changes steep ground only. One Warp stamp on the GPU differs from the CPU stamp by at most 1 level.

Warp is not wholesale procedural world generation. The stroke sets the place and the amount of the warp, and the ground outside the brush does not change. Warp is a test of a brush that breaks up round shapes, and the design of version 1 does not include it.

The tenth brush mode, Ridge, is the inverse of Carve. It raises the land under the brush by an amount that grows with the distance from the nearest river, so the crest between two valleys becomes sharp. The amount grows in a straight line from zero on a river to the full strength of the brush at the largest distance, and it stays at the full strength past that distance. The largest distance is about 4 cells of the map in use, so the crests are closer together in the window. Ridge reads the window where the window covers the ground, and the channel map on the other ground. With no channel map, each place is at the largest distance. Ridge does not change the sea floor. One Ridge stamp on the GPU differs from the CPU stamp by at most 1 level. Ridge is a test of a brush that follows the rivers, and the design of version 1 does not include it.

The eleventh brush mode, Deposit, fills pits and valley floors, as sediment does. Each cell of the map in use has a fill level. A cell in a pit has the level of the rim of the pit, which is the level where the water leaves the pit. A river cell has the level halfway from its bed to its lower bank. A bank is the highest ground at one side of the river. The search for a bank goes 1 to 3 cells from the river, and a larger river has a longer search. Thus the lower bank is the level where the water leaves the valley. A cell also takes the fill level of the cell that takes its water, if that level is higher. Thus the fill levels do not go down against the flow, and the floor of a river continues into the mouths of its streams. A texel takes a blend of the fill levels of the 4 cells around it. A Deposit stamp moves each texel below its fill level toward that level, by the part that the flow of the brush gives. The lowest ground is near the river, so it rises the most, and the floor becomes flat. Ground at or above its fill level does not change. Thus the stamp lowers no ground, and no ground goes above the rim of the pit or the lower bank of the valley. Deposit does not change the sea floor, and the Strength slider has no effect in this mode. The fill levels are from the rivers at the start of the stroke, so a second stroke fills a valley further. Deposit reads the window where the window covers the ground, and the channel map on the other ground. With no channel map, Deposit changes nothing. One Deposit stamp on the GPU differs from the CPU stamp by at most 1 level. Deposit is a test of a brush that adds sediment, and the design of version 1 does not include it.

The twelfth brush mode, Ocean ridge, lays a mid-ocean ridge along the stroke. The stroke is the axis of the ridge, where new sea floor forms. A ridge is not a sum of stamps. Each texel near the line gets an age, and its shape follows from that age and from the history of the axis. The model uses published geophysics.

The age of a texel is its distance from the axis divided by half of the spreading rate. The depth follows the age curve GDH1 of Stein and Stein (1992). The brush scales that curve, so the axis is at the Crest elevation and the ground at the brush radius keeps its level. A noise with features of about one brush radius makes the rise swell in some places and sink in others, so the lines of equal depth wander. Another noise lowers the whole rise in some places, the crest included.

The axis has segments. Transform faults divide the axis into groups of segments, and small offsets divide each group. A segment between two small offsets is about 50 km long on a slow ridge and about 140 km long on a fast ridge. Each boundary leaves a trace on the flanks. One seeded history of the spreading direction bends all the traces of a side together, so no trace is straight. An offset that moves along the axis leaves an oblique trace or a V. The age steps at a trace, so the depth also steps there. That step is a fracture zone. A large offset leaves a deep, wide trough, and a small offset leaves a broad, shallow trough. Old troughs stay deep. A smooth field moves the traces along the axis. The move grows with the age, so young traces are straight and old traces bend at random, and traces near each other bend together. On old floor, the trace of a small offset also has its own path of straight pieces with sharp kinks, and its trough breaks into pieces with gaps between them. A nodal deep is at each corner of the axis and a transform fault, and the segment ends are deeper than the segment middles.

The abyssal hills are fault blocks that form at the axis and move away from it. The magma supply sets the spacing and the size of the faults, from the tables of Behn and Ito (2008). Low supply gives large faults far apart, and high supply gives small faults close together. Each fault has short pieces that step past each other, and each block has a steep face toward the axis and a round top and foot. The supply changes along each segment and with age, so the roughness changes in bands along the axis. Sediment fills the low places more on old floor, and slides off the scarps make the hills lower than the throw of their faults. Each fault is averaged over the area of a texel, so faults smaller than a texel show their mean roughness.

A slow ridge has an axial valley, and a fast ridge has an axial high, as Chen and Morgan (1990) describe. The walls of the valley are steps of large faults that face the axis, and their tops are the rift mountains. The floor of the valley has lava hills and a volcanic ridge with gaps.

The Crest stepper goes from -6,000 to 6,000 m, and it starts at -700 m. The Spreading stepper sets the full spreading rate from 10 to 150 mm/yr, and it starts at 25 mm/yr. The Magma slider moves the magma supply from -25 to +15 percent of its normal value for that rate, and it starts at 0. The Segment stepper sets the mean distance between transform faults from 100 to 1,500 km, and it starts at 400 km. The Offset stepper sets the largest offset from 0 to 500 km, and it starts at 100 km. An offset is at most half of the brush radius. A line below these settings shows the age of the floor at the brush radius.

The ridge raises the ground. Only the fracture zones, the nodal deeps, and the axial valley can go below the old ground. The ground farther from the line than 1.5 brush radii does not change. The highest relief bends below the Crest elevation, and the ridge gets lower and narrower toward each end of the line.

After the pen goes up, the app sends the points of the line to the GPU in plans. A plan holds at most 16 new segments, the older segments near them, and one rectangle for each face. The GPU runs the passes of the brush and the frames of the UI in one queue, in order, so a long pass makes the UI wait. Thus a plan of an ocean ridge goes to the GPU in strips of at most 1 million texels. A texel of a ridge depends only on its ground and the plan, so the strips give the texels of the whole plan. The strips of one frame go after the GPU finishes the strips before them, and after the first strip they hold at most 1 million texels of ground. For each plan, the app writes the ground from before the stroke into the rectangles, and one pass for each face draws the ridge there. The CPU heightmap holds that ground until the end of the stroke. A plan holds at most 128 segments. If more segments are near, as in a dense scribble, the plan leaves out the farthest ones, and a part of the older ridge can go flat. The GPU result of a stroke differs from the CPU result by at most 2 levels. Two equal strokes on equal ground with the same seed give equal results, and one undo step puts back the ground from before the stroke.

The pen draws the center line of the ridge. The canvas shows the line with no brush circle, and the ridge shows after the pen goes up. The brush radius at the first point sets the width of the ridge. After the pen goes up, the ridge is held. A held ridge shows on the GPU, and the CPU heightmap does not have it yet. The buttons "Discard" and "Apply" show at the bottom of the canvas, and the brush settings show a hint. Beside the buttons, the state "Updating…" with a spinner shows while the ridge follows a change, and "Ready" shows after. When the settings of the brush hold still for 250 ms, the app sends the plans of the line again with the new settings, so a slider drag does not start a redraw in each frame. A change during a redraw starts the redraw again. "Apply" waits for the ridge of the last settings. Each plan writes the ground from before the stroke into its rectangles first, so the old ridge shows until the new one covers it. A change of the size of the brush sets the width again. A smaller width makes smaller rectangles, so the app first writes the ground from before the stroke into the rectangles of the old ridge. The Flow setting scales the flow of each point. The button "Apply" or the Return key puts the ridge into the heightmap as one undo step. The button "Discard", the Escape key, or an undo puts back the ground from before the stroke, with no undo step. A new stroke, another mode, another tool, another layer, or an import applies the held ridge first. A held ridge does not go into the project file until it is applied.

Ocean ridge is not wholesale procedural world generation. The stroke sets the line, the width, and the height of the ridge. The seed sets the pattern near the stroke only.

The thirteenth brush mode, Range, makes a mountain belt from one stroke. A belt has a high core along its axis, lower foothills at its sides, and many long ridges side by side. As for Ocean ridge, a belt is not a sum of stamps. Each texel near the line gets a place on the line: the distance along the line from its start, and the signed distance from the line.

The cross-section is the sum of two curves of the distance from the line. The core is flat out to 0.15 of the brush radius and falls to zero at 0.55 of the radius. The foothills fall in a smooth curve from the line to zero at the brush radius. The core has 55 percent of the height, and the foothills have 45 percent. Thus the brush radius is the half-width of the belt. The belt gets lower and narrower over 1.2 brush radii at each end of the line.

The ridges are pieces in bands across the line. The Spacing setting is the mean distance between two bands. A piece is about 8 spacings long, and its ends are seeded. The ends of the next band are at another seeded place. Each piece is a little oblique to the line, so its crest moves half a spacing sideways along its length. At an end, one piece goes down while the next piece, half a spacing to the side, comes up. Thus the ridges end and start again beside each other, and a low saddle is between them. Each piece has a seeded height and a small seeded shift across. The ridges take 80 percent of the height at each place, and the ground between them takes 20 percent. Thus the ridges are high in the core and low in the foothills.

The Strength slider has the name Height in this mode, and it sets the height of the core. The pen pressure scales the height, and the mouse gives the full height. The Spacing slider goes from 5 to 300 km, and it starts at 30 km. The spacing is not less than 6 texels or more than half of the brush radius. The Seed stepper sets the seed of the world, as in the Warp mode. The mode has no Hardness slider.

The app sends the line to the GPU in plans, as for Ocean ridge, and the belt shows while you paint. The GPU result of a stroke differs from the CPU result by at most 2 levels. While you paint, the worker of the Uplift mode erodes the belt. A request covers a part of the line that the next points do not change. The worker raises its cells under that part to the level of the belt one time, and then it runs 4 Erode steps there. The rate is the Erosion setting times the square root of the number of cells in the brush radius, divided by 4. The Erosion, Wind, and Rain shadow sliders are the same as for Uplift. At 0 percent, the stroke makes no steps. The app keeps the results of the steps, and it applies them after the last plan of the stroke. The valleys between the ridges collect the water, and the rivers run along the belt. A river leaves the belt through a saddle between two pieces. Painting does not wait for a step, and one undo step puts back the ground from before the stroke.

Range is not wholesale procedural world generation. The stroke sets the axis, the width, and the height of the belt. The seed sets the pattern near the stroke only.

The fourteenth brush mode, Push, moves the ground under the brush in the direction of the stroke, as the smudge tool of a paint program moves color. With it, you move a coast or bend a range, and you do not lower the old ground and paint the new ground. Each stamp has a motion, which is the move of the pen from the stamp before it. The first stamp of a stroke has no motion and changes nothing. Each texel under the brush takes the height of the ground behind it, at the motion times the weight of the brush. The weight is the falloff of the brush times the flow, so the pressure of a pen sets the distance. At full weight, the ground moves with the pen. The mode has no Strength slider.

Push uses the steps of Warp after the offset. The offset is not larger than the distance to the brush edge minus 3 texels, so the motion goes to zero at the edge and the edge shows no step. Each new height is between the lowest height and the highest height under the brush, so Push adds no height, and flat ground stays flat. The height at the offset place is a blend of the 4 texels around it, also past a face edge, so a stroke across a face edge has no seam. One Push stamp on the GPU differs from the CPU stamp by at most 1 level. A stroke is one undo step.

The fifteenth brush mode, Noise, adds fractal noise under the brush. Painted ground is smooth at each scale below the brush radius, and the noise gives it detail. Fractal noise is a sum of noises of several sizes. Each of these noises is an octave. An octave has features of half the size and half the weight of the octave before it. The first octave has features of the size of the Scale setting, and the smallest octave has features of 2 texels or more. The sum has 8 octaves at most. Each octave is the value noise of Warp, with a seed that comes from the seed of the world. The noise takes the 3D point of the texel on the sphere. Thus a face edge shows no seam, and a feature has the same size at each place on the globe.

Each Noise stamp adds the value of the noise to each texel, times the weight of the brush. The value goes from -1 to 1, so the noise raises some ground and lowers other ground. In this mode, a Raise slider and a Lower slider take the place of the Strength slider. A positive value is multiplied by the raise, and a negative value by the lower. Thus Raise sets the largest rise of one pass, and Lower sets the largest drop of one pass. Each slider goes from 0 to 6,000 m, and each starts at 1,500 m. With Lower at 0, a stroke does not lower the ground, and with Raise at 0, a stroke does not raise it. The Scale slider sets the size of the largest features, from 5 to 2,000 km, and Warp uses the same setting. The Seed stepper sets the seed of the world, as in Warp. Two equal strokes on equal ground with the same seed give equal results.

The Ridged switch selects the ridged variant of the noise. That variant folds each octave at zero: its value is 1 minus 2 times the absolute value of the noise. The fold gives sharp crests where the noise crosses zero. The mean of the ridged noise is above zero, so a ridged stroke raises the ground. While the Ridged switch is on, an Invert switch shows. It turns the ridged noise upside down, which gives sharp valleys, and a stroke then lowers the ground. The Relief slider makes the noise grow with the height of the ground above sea level, so plains stay calm. It goes from 0 to 100%, and it starts at 50%. At 100%, the noise has no effect at sea level and below, and it has its full effect at 2,000 m above sea level. At 0%, the height has no effect. The relief needs heights in meters, so the slider shows on a height layer only. On another layer, the noise has its full effect at each value.

The Grain slider makes the features of the noise long in the direction of the stroke, as in a fold belt of long parallel ridges. It shows the ratio of the length of a feature along the stroke to its width, from 1× to 10×, and it starts at 1×. At 1×, the noise has no direction. Each stamp takes the direction of the stroke from its move since the stamp before it. That move and the stamp center set a great circle. The noise takes the 3D point of the texel with the part in the plane of the great circle divided by the ratio, and the part across the plane does not change. Thus the features are longer along the great circle by the ratio. All the stamps of a straight stroke are on one great circle, so they add the same noise, and a stroke in the other direction adds the same noise too. On a curved stroke, the great circle turns from stamp to stamp, and the grain follows the curve. On a sharp curve, the noise of the stamps differs more, so the features are softer. Each stamp adds its noise to the ground, so two strokes of different directions add their noises where they cross, and the ground shows no seam. The first stamp of a stroke waits for the second stamp, which gives its direction. A tap gives one stamp with no direction.

One Noise stamp on the GPU differs from the CPU stamp by at most 1 level. In the part of the brush with full effect, each stamp of a stroke gives a texel the same change. If that change is near a half level, the GPU can round it the other way at each of those stamps, so a stroke differs by a few levels.

Noise is not wholesale procedural world generation. The stroke sets the place and the amount of the noise, and the ground outside the brush does not change. Noise is a test of a brush that adds detail, and the design of version 1 does not include it.

The sixteenth brush mode, Basin, makes a watershed from two strokes. A watershed is the area that drains to one river. The first stroke is the outline of the basin, and the outline closes from its last point to its first point. The second stroke is the main river: the first point is its source, and the outlet is where the line leaves the outline. If the line does not leave the outline, its last point is the outlet. The part of the line before its first point inside the outline is not used. Sea level is the base level of the basin. The ground below sea level is outside the basin and does not change, so the coast is also an edge of the basin, and a main river that reaches the sea has its outlet at the coast. The points of both strokes are close together, so the main river keeps the small bends of the stroke. A tributary is a river that joins the main river. The mode changes the ground that is there: it adds relief to it and erodes it. It does the work after the second stroke ends.

The half-width of the basin is the area of the outline divided by its length. The mode first makes the network of the rivers on the coarse cells of one window, as the Erode mode does. The window holds the outline with 8 cells or more in the half-width, and its cells are not larger than the cells of the coarse copy. A larger outline is cut at the sides of the window. The window continues past a face edge, so a basin across an edge has no seam. The area of the basin is the cells inside the outline that the main river reaches through cells of the area. The line gives a chain of cells from the source to the outlet, and each cell of the chain drains to the next one. The distance to the main river is the distance through the cells of the area, so an outline with a bend also drains to the main river. A flood out from the main river gives the drains of the other cells. It takes the cells of the area from the lowest level of the start surface up, and each cell drains to its steepest neighbor that the flood took before it. A fixed random weight from 0.7 to 1.3 for each pair of cells scales the slope, so the streams do not follow the grid. A cell at the side of the area takes no water if another neighbor can. Thus all the water of the network drains to the outlet, and the streams follow the valleys of the start surface.

The start surface rises across the area, from the main river to the outline, and a little along it, from the outlet to the source. The old ground goes into it, so the streams follow the valleys of the old ground. Seeded value noise of the direction gives it bumps. It has 3 octaves or more, down to bumps of 4 cells, so the streams bend at each Density setting. The largest bumps are 1.6 times the tributary distance in size, and the smaller octaves bend the streams. Stream-power erosion with uplift then runs on this surface, with the implicit solver of Braun and Willett (2013). The erosion of a cell is its slope times the water that drains through it to the power of 0.6. A step of the solver goes along the cells in drain order, from the outlet up, so each cell takes the new level of its receiver, and the step is stable at each size. After 24 steps, or when the drains stop changing, the levels go to the steady state of the last drains: each cell is above its receiver by its length over its water to the power of 0.6. The water grows down each river, so the slope gets less, and the profile of the main river is concave.

A tributary is a river with this much water or more: 0.8 times the Density setting times the half-width, in cells of even rain. The rain of the Erode mode gives the water of each cell, from the ground before the stroke. Thus less rain gives fewer tributaries. The Density slider goes from 10 to 500 km, and it starts at 40 km. It is not less than 4 cells or more than 4 times the half-width. The Seed stepper sets the seed of the world, as in the Warp mode, and another seed gives another network.

The main river stays at or below the old ground. Its floor at each cell is the lowest old ground at that cell, at the cells next to it, and upstream of it, and it is not below sea level. The steady state gives the concave shape of its profile, from the floor at the outlet to the floor at the source, and the floor caps the profile. Thus the main river cuts a gorge through a ridge of the old ground, and on flat ground it is nearly flat. Its level is the depth of its channel above its bed, and it goes down at each cell to the outlet.

The relief of the basin rises from the main river and goes onto the old ground. It is 75 percent the steady state of the network above the main river and 25 percent an even rise from the main river to the outline, scaled to the Height setting. The steady state above the main river keeps half of the rise of the main river, so the hills near the source are higher. The mode finds the height of the old ground above the main river near each cell. This is a mean over half the half-width, from the level of the main river at the nearest place along the line. Where this height is not more than the Height setting, the relief goes onto the old ground. There, where the old ground is already higher than the main river, the relief is less by 70 percent of that height. Where the old ground is higher, the basin cuts its valleys into it. The ground rises from the main river by the Height setting times the shape of the relief, and by the rest of the height of the old ground times the square root of the shape over the highest shape near the cell. The two ways blend over one Height setting. Thus the divides stay near the old ground, and a basin across mountains and lowlands has deep valleys in the mountains and low hills in the lowlands. The relief fades out over 40 percent of the half-width from the outline, so the basin meets the old ground with no rim. If the main river ends inside the outline, the relief opens in a gap past its last point, in the direction of the end of the line. This gap is the mouth of the basin. Then each cell goes above its receiver: a stream cuts a gap down through a barrier of the old ground, and the hollows that are left fill. The cells next to the main river are 2 percent of the height of the relief above it.

Finer levels then add detail, down to cells of one texel or to 1,024 cells along a side of the window. Each level has cells of half the size of the level before it. It takes the change of that level from a place that a noise moves by 1.5 cells of that level at most, so the valleys of that level bend at the scale of this level. The move fades out within 3 of those cells of the main river. The level adds rough ground at its scale, and erodes it with 4 implicit steps of the stream-power law, on the flow of a flood that fills the pits. The Erosion slider of the brush panel sets the erodibility. It is 0.02 at 0 percent and 1 at 100 percent, and it changes by the same factor for each step between them. At a low setting, a cell with little water hardly erodes, and only the streams that collect much water cut valleys. At 100 percent, each slope gets a gully down each line of cells. The setting starts at 50 percent, and the Uplift mode and the Range mode use the same setting. The rough ground of the first finer level is 3 percent of the height of the relief at the cell, and each next level has 55 percent of the level before it. A step cuts a cell by 3 times the rough ground of its level at most, so each level adds valleys at its own scale. A pit of 2 steps of rough ground or less fills to one step below its rim, so a hollow of the rough ground stays shallow. A deeper hollow of the old ground stays. The main river keeps its profile, and it stays at or below the old ground of the level. Hillslope creep then rounds the crests, and it removes the steps that the grid gives to the gullies. Thus the old ground and the network shape the large valleys, and the gullies of all sizes come from the erosion. Then a flood from the side of the area and from the main river cuts a path out of each hollow of the finest level, so its water leaves it.

The Age setting goes from young land at 0 percent to old land at 100 percent, and it starts at 50 percent. At the middle age, the creep of each level is as above. Toward young land, it is up to 4 times less, so the crests are sharp. Toward old land, it is up to 4 times more, so the slopes are round. Past the middle, the ground near the large streams also goes down toward the level of the stream, so the valleys have flat floors. A floor is 15 percent of the tributary distance wide for a stream with the water of a tributary, and it grows with the square root of the water, to 3 times that width.

The Lakes setting goes from 0 to 100 percent, and it starts at 0. The Age slider and the Lakes slider are in the brush panel in this mode, in both layouts. At 100 percent, the basin has one lake for each 2 tributary distances along the main river. A lake stands behind a dam on a stream with the water of a tributary or more. The dam raises the ground within 12 percent of the tributary distance of a place on the stream, to a level above the stream of 10 to 30 percent of the height of the relief. The valley above the dam holds the water. A lake is 30 percent of the tributary distance or more from the main river and from the outline, and two dams are one tributary distance apart or more.

The texels take the change of the finest level, and rough ground of half a cell below its cell size, which fades out at the main river. The main river is cut into the texels along the drawn line, with the level and the water of the cells of the main river at the same place along the line. The tributaries of the finest level are cut along their cells. Both are channels of the Carve mode, with the default channel width of 0.6 km and a depth of 10 m for the largest river. The basin mode has no Channel width setting. The change goes to zero over 10 percent of the half-width from the outline and the coast, and the texels outside the outline do not change. Within 10 m of sea level, a cut of a texel gets less as it goes down, so it does not reach sea level, and the lowlands do not go flat at the sea. Thus a basin at a coast needs no Floor setting. Thus the bed of the main river meets the old ground where it leaves the outline. The Floor setting and the Ceiling setting apply to each texel. The Strength slider has the name Height in this mode, and the mode has no Hardness slider and no Flow slider. The outline sets the size, so the brush panel has no Radius slider in this mode, and the Size slider and the Flow slider of the iPad rail are off.

While you draw, the canvas shows the outline and the main river as thin lines, with no brush circle, and the ground does not change. The outline ends at the pen while you draw it, and it closes when the pen goes up. It stays on the canvas until you draw the main river. The basin settings show a hint for the next stroke. While the outline waits for its main river, a card at the bottom of the canvas shows the hint "Draw the main river." and the button "Clear", which removes the outline. The card is in the place of the card of a held stroke. A switch to another mode also removes it. When the second stroke ends, a worker thread makes the basin from a copy of the heightmap. Painting does not wait for it. The app then sends the new texels to the GPU, and the basin is held, as a held ocean ridge is. The outline and the main river stay on the canvas. When the settings hold still for 250 ms, the worker makes the basin again from the same lines, after the basin before it arrives. When the new basin arrives, the app writes the ground from before the stroke into the rectangles of the old basin, and then it sends the new texels. The buttons "Apply" and "Discard" end the held basin, and one undo step puts back the ground from before an applied basin.

Basin is not wholesale procedural world generation. The outline sets the area, and the second stroke sets the main river and the outlet. The seed sets the pattern of the tributaries inside the outline only, and the ground outside the outline does not change.

The seventeenth brush mode, Terrace, pulls the ground toward a set of flat step levels. Mesa country and a stepped coast have flat levels with steep sides between them, and Flatten gives one level only. The Step setting is the height between two step levels. It goes from 10 m to 3,000 m, and it starts at 200 m. Sea level is a step level, and so is each multiple of the step above and below sea level. A Terrace stamp moves each texel toward the nearest step level, by the part that the weight of the brush and the flow give. After many stamps, the ground between two step levels is flat, with a steep side where the nearest step level changes. A texel does not cross sea level. Sea level is land, so the highest step of the sea floor is one level below sea level. In this mode, the Step slider takes the place of the Strength slider. The setting is a session setting, and it is not in the project file. Terrace needs heights in meters, so it is in the Terrain cell. One Terrace stamp on the GPU differs from the CPU stamp by at most 1 level.

The eighteenth brush mode, Shape, sets the age of the land. Old land has convex slopes and round crests. Young land has concave slopes and sharp crests. Painted land and eroded land have one kind of slope everywhere, so Shape lets one range look older than another. For each texel, a Shape stamp finds the lowest level and the highest level on a grid of 9 by 9 texels. The grid reaches half the brush radius on each side of the texel. The stamp moves the texel toward a curve between those two levels, by the part that the weight of the brush and the flow give. The Shape setting goes from Old to Young, and it starts at Old 50%. Toward Old, the curve raises the middle of each slope, and the slope at the top of the curve is less steep. Toward Young, the curve lowers the middle of each slope, and the slope at the top of the curve is steeper. At the middle setting, Straight, the curve is a straight line. The lowest texel and the highest texel near the brush do not move, so the crests and the valley floors keep their heights. The river cells keep their receivers. A hillslope cell with two neighbors at almost the same score can change its receiver from a straight neighbor to a diagonal neighbor. A texel does not cross sea level. The curve moves with the ground, so the flow of each stamp is small, and one stroke applies the curve about once. A second stroke over the same ground adds to the change. In this mode, the Shape slider takes the place of the Strength slider. The setting is a session setting, and it is not in the project file. Shape needs sea level, so it is in the Terrain cell. One Shape stamp on the GPU differs from the CPU stamp by at most 2 levels, and a stroke by at most 4 levels.

The brush panel has a Floor setting and a Ceiling setting. Each one has a switch and an elevation in meters. Both switches are off at the start, and the elevations start at 0 m and 1,000 m. In the iPad layout, the elevation is a stepper with steps of 50 m, and it shows while its switch is on. The two limits apply to all the modes. The brush changes only the ground from the floor to the ceiling, and that ground does not go below the floor or above the ceiling. Ground below the floor or above the ceiling does not change. Thus an Erode stroke with a floor of 0 m keeps the land above the sea, and an Uplift stroke with a ceiling gives a plateau. A Smooth stroke with a ceiling does not lower the peaks above it. One pair of texels of a Weather stamp moves at most a quarter of the room to each limit, and a pair with a texel outside the limits does not move. A texel is in 4 pairs at most, so no texel crosses a limit, and the sum of the levels stays. A texel within 3 levels of a limit does not move toward it. In the Erode mode and in the Uplift mode, the cells of the worker keep the limits, and so do the texels. One GPU pass has one pair of limits, so a group of stamps ends where the limits change. The two settings are not coupled. If the floor is above the ceiling, no ground moves.

1. The prototype is a vertical slice through phases 2, 4, 6, 8, and 9. It does not finish any of them.
2. In the window, GPU Vello draws the maps and the furniture of the atlas from the display list of `vale-render`. With no window, `vello_cpu` draws them, so the headless commands and the tests need no GPU. `vello_cpu` also draws the PNG files. The PDF export uses Krilla, and text in the PDF stays text.
3. `vale-store` holds the project in memory, and it reads and writes the world, the vector layers, and the raster records as a GeoPackage file. One save writes all the vector layers again, and it writes only the raster tiles that changed. Each save that changes the file is one step of the undo log. A step holds a changed vector layer as a whole. In memory, a feature ID is its index in the layer. With `--project`, the app loads the project file at the start and saves half a second after a change. When a stroke or an import ends, the app saves at once, so each of them is one undo step. While you hold a control, the save waits, so one drag is one undo step. On iPad, the app saves each change that waits when it stops being active, and again when it goes to the background. A stroke that still waits for its texels at that time stays open, and it is not in the file. The row "Save" of the menu of the worlds saves each change that waits at once, and the File menu has the same row with the shortcut Ctrl+S. The save mark turns while a change waits, and for 0.9 seconds after a save. After that it is a tick. After a save that failed, it is a warning sign. In the desktop layout, the mark is next to the File menu. The iPad layout has no save mark. After a save that failed, a banner at the top center, below the top row, says "Could not save. Changes are kept and saved again." It stays until a save succeeds. A layer record holds the name, the visibility, the style, and the place of the layer in the draw order, so undo and redo include them. An imported layer goes above the layers of its kind, with polygons below lines and lines below points. The globe draws one pass for each visible raster layer, between the shapes of the vector layers. The drawing starts at the top raster layer that is visible and has an opacity of 100 %, because that layer hides each layer below it. An image layer never hides the layers below it. The blend mode of a raster layer or an image layer mixes it with the raster layers and the image layers below it, up to the next vector layer. The graticule and the soft edge of the globe are above the top raster layer. Each visible height layer shows its own rivers, and with their lakes they cost 29 MB of GPU memory for each such layer, outside the 256 MB of the copies. The small rivers of a close view show on the active layer only. A stroke or an import ends, and the app saves it, before another layer becomes the active raster layer. A thread reads the tiles of a layer that just became active with its own connection to the file, one row of tiles at a time, and the UI draws each frame while it reads. With no project file, each raster layer keeps its tiles at the full face size in main memory. A new raster layer, a removed one, a hidden one, a moved one, a change of its opacity, and a stroke are one undo step each. The step that moves a file to format version 9 empties the undo log. If the style of a raster layer has no colors, the app puts the colors of the raster record into the style when it opens the file, and it empties the undo log. The picture of the globe for the start screen blends the visible raster layers and the shapes of the visible vector layers in the draw order, with no symbols. The readout shows the value of the active raster layer if it is visible. If not, it shows the value of the top visible raster layer, with the name of that layer. The import of a heightmap makes a height layer with the name "Height" if the world has none. A change of a raster layer waits for its save until the texels of the stroke are back from the GPU. When the app closes, a stroke that still waits for its texels does not go to the file. A raster layer of a project file keeps its face size, and `--face-size` sets only the default face size of a new layer. If the device cannot hold a face of that size, the app does not show the layer and tells you its name, and the file keeps its record and its tiles. The save runs on the UI thread.
4. `vale-import` reads GeoJSON, and it reads PNG and TIFF images as 16-bit greyscale. It copies the data, and there is no command to replace a file.
5. `vale-sphere` clips with one simple method: rotate, unwrap, and clip in a plane. A polygon that covers more than half of the sphere is not supported. A ring closes along the short longitude way. `geo` and `rstar` are not dependencies yet.
6. `vale-style` has rule-based styles, with a solid fill, the stroke types, a marker in five shapes with a solid or hatched fill, an SVG point symbol, a scatter, and the label settings of each layer. Each map has label classes. The style editor edits the filter, the scale range, the stroke, the fill, the point symbol, and the scatter of each rule. Only the size and the rotation of a point symbol can come from a field. On the globe, the scale denominator comes from the radius of the world and the radius of the globe on the screen.
7. The map pipeline (query, clip, project, style, label, emit) lives in the library part of `vale-app`, in modules that do not use egui.
8. A map stores its projection as a PROJ string with no radius. The app reads the string back into one of ten presets with its center, standard parallels, and an oblique aspect, and it adds the radius of the world when it builds the projection. The project keeps custom projections as named PROJ strings. The Projection tab of a frame lists the presets and the custom projections, edits the parameters, and saves the projection under a name.
9. `vale-labeler-demo` stays as the regression test of the labeler. It keeps its own GeoJSON reader and its two hand-written projections, and it now draws through the display list of `vale-render`.

The prototype leaves out the following.

- Undo and redo with no project file. Then undo and redo are for brush strokes only.
- Rasters and blend modes in the PNG and PDF export, regional source extents over a world source, SVG and Shapefile import, the command Replace from file, and georeferencing with extents or control points.
- The points, the symbols, and the scatter fills in the flat view of the globe workspace.
- The rows "From file…" and "From tool" in the menu of the new layers.
- Pattern fills, texture fills, hatch fills of polygons, and edge effects, and style properties from expressions in the style editor other than the size and the rotation of a point symbol.
- Label fallbacks, leader lines, and manual label changes (pin, move, exclude).
- The overview of the pages, page templates, SVG export, and tiled raster export.
- Tissot circles.
- All editing tools other than the freehand line tool, the freehand polygon tool, point placement, the Select tool, reshape, and the attribute table: vertex editing.
- Wholesale procedural world generation. This is a permanent non-goal.

### Globe prototype

The globe prototype is the crate `vale-globe-proto`. It tests two things ahead of phase 1: that a brush on a cube map stays round at every place on the sphere, and that egui can take Apple Pencil input on iPad. The heightmap and the brush come from `vale-terrain`. The command `cargo run --release -p vale-globe-proto` opens the window, and `scripts/globe-proto-ipad.sh` builds the app and starts it on a connected iPad.

The prototype has a pressure brush with the four modes, the stepped preview in one shader pass, a freehand line tool, and a panel that shows what the pen delivers. The unit tests of `vale-terrain` make sure that one stamp covers the same ground at the equator, at a pole, on a face edge, and at a cube corner.

It differs from the design in four ways.

1. The brush stamps on the CPU, and the prototype sends the changed texels to the GPU. The design stamps in wgpu shaders, and `vale-app` does.
2. The heightmap has no project file, and the GPU texture holds six full faces.
3. Pen input comes through egui touch events. A touch with a force counts as a pen, because on iPad only Apple Pencil has a force.
4. Hover, tilt, and the 240 Hz pen samples do not arrive, because winit 0.30 does not read them on iOS. If the iPad test shows that the app needs them, a UIKit gesture recognizer below egui can supply them.

A first test on an iPad with Apple Pencil on 2026-10-08 gave these results: painting and navigation are smooth, pressure works, and palm rejection works. The app gets 120 pen samples per second, and it gets no hover events. Both results match item 4. `crates/vale-globe-proto/README.md` lists all the tests.

This document sets no dates. The labeling work continues in parallel with the phases, because its quality grows with test cases and not with a deadline.

## Risks and open questions

The largest risk is the scope of the labeling engine. To contain it, the library came first, and it grows in parallel with the phases.

| Risk | Response |
| --- | --- |
| The labeling engine takes years to reach Maplex quality. | Build it first as a library. Ship strong manual control early, so that a weaker engine is still usable. |
| Vello, Parley, and Krilla are young libraries. | The display list isolates them. Skia is the fallback renderer, because it draws to screen, PDF, and SVG. |
| egui 0.36 and wgpu 30 are new, and Vello must keep the same wgpu version as eframe. | The display list isolates Vello, and `vello_cpu` draws the same list with no GPU. |
| egui limits the panels and tables. | Keep all logic in the core crates. If a real limit appears, change the shell. |
| PROJ is hard to package on Windows. | Use the bundled build and add a Windows build to CI in phase 0. |
| When you replace an imported vector file, features lose identity. | Use element IDs first and geometry matching second, and report each lost match. |
| Painting needs a fast, steady stroke, and a slow brush makes the tool useless. | Stamp on the GPU and repaint only the tiles under the brush. Measure the stroke delay in phase 1. |
| The translucent macOS window needs a transparent title bar, an `NSVisualEffectView` behind the window, egui panels with a transparent fill, and a wgpu surface with alpha. | Make a test window with winit, wgpu, and the `window-vibrancy` crate before the desktop layout is built. If it fails, the bars and the dock are opaque. |
| One heightmap resolution does not fit both a world and a small region. | Each raster layer has one face size, high enough for regional maps. Finer tiles for a region, in levels, come after version 1. The tile key has a level field for them. |
| egui gives no hover, no tilt, and only 120 pen samples per second on iPad. | The iPad test of the globe prototype passed for painting, pressure, and palm rejection. A UIKit gesture recognizer below egui reads hover, tilt, and the 240 Hz samples in `vale-app`. |
| Reprojected rasters look soft. | Show the resolution of each source against each map frame, and support regional sources. |

One question is open, and eight are decided.

- [x] Decided: heightmap painting on the globe, the toolbox, and freehand lines are in version 1. A full vector drawing tool set is not.
- [x] Decided: the globe and the toolbox come before styling and labeling in the app. They are phases 1 and 3.
- [x] Decided: the shell stays egui. The globe prototype ran on an iPad with Apple Pencil, and painting, pressure, and palm rejection work. Hover and the 240 Hz pen samples need a UIKit gesture recognizer below egui.
- [x] Decided: the app and the labeler use a dual MIT and Apache-2.0 license.
- [ ] Does export need CMYK for commercial print?
- [x] Decided: a project is one file and not a folder, and an import copies its data into that file. One file keeps the transactions, QGIS reads it directly, and it is one item on each platform. A folder gives only readable diffs in version control. A sync service can break a SQLite file that is open, so the app edits a working copy and writes the project back as a whole file.
- [x] Decided: the app is named Vale, and the crates have more specific names.
- [x] Decided: the world does not mark one raster layer as its height. A raster layer with the unit `m` is a height layer. Each tool takes a layer or works on the active layer, so a mark adds only a rule for the deletion of a layer.
- [x] Decided: the tool column keeps its six tool cells when the active layer is not a raster layer and when the world has no layer. The Sculpt cell and the Terrain cell are disabled. The column then does not move when you select another layer.
